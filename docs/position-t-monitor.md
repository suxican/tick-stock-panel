# 持仓盘中做 T 监控：首版使用与接入说明

入口为 `/lots` → **持仓做 T**。原有「批次提醒」继续使用原数据和接口，可在选定做 T 账户后点击「从批次提醒同步」添加个股，批次记录不等于已核对的账户库存。新增功能仅支持普通现金账户 A 股的人工登记、提醒与保守模拟，不包含券商接口或自动下单。

## 使用步骤

1. 添加人工或模拟账户，核对资金的交易日、可用金额、券商冻结金额及可用字段是否已经扣除冻结。
2. 添加持仓。总持仓、当日可卖、核心下限、日终目标分别录入。可卖不明确时留空，系统暂停执行判断。首次由未知核对为明确可卖，以首次确认的剩余额度建立保守当日数量预算，不倒推日初库存。
3. 指定证券板块、比较指数和板块目录目标。板块无成分或行情覆盖不足时暂停。
4. 在「策略与费用」中确认券商收费合同、最低佣金、生效日期、费用包含关系及分钟时间标记的起始／结束语义，然后启用账户监控。研发默认参数不代表已验证的盈利参数。
5. 候选只测算，不占用资金。接受计划时再次校验行情、版本和资源，并在 SQLite 事务中预留。候选并行出现不表示可以同时执行。
6. 委托状态和实际成交分别登记。价格触及、已读、关注或委托状态中的累计成交量都不会自动生成实际成交。人工卖出所得须显式确认已可用，或在资金核对中明确更新可用金额后才能计入回补资源。
7. 在「未完成计划」处理第二笔。部分成交只跟踪实际未匹配股数；撤单未确认不释放相应资源。收盘未完成保留隔夜记录，不以收盘价虚构补齐。
8. 次交易日重新核对账户和可卖额度。实时账本不按自然日零点解锁库存，也不会自动刷新人工核对时间。后台服务正常运行时关闭页面仍继续监控；关闭后端或电脑则停止。

### 从批次提醒同步

选定账户后，在「持仓监控」点击「从批次提醒同步」。同一股票的有效批次按股数合并，总股数为批次数量之和，参考成本按股数加权；成本仍标记为人工参考，不代替券商成本。仅接受证券目录中已确认的 A 股股票，数量、成本无效或非股票的记录会显示跳过原因。同股包含无效批次时整股跳过，避免只同步部分数量。

同步只添加该账户尚未存在的股票。已有持仓、委托、成交和资源预留保持原样，重复同步不会重复增加股数；批次后续修改或删除不会自动覆盖做 T 账本，需要在做 T 持仓中核对。同步记录保留批次来源和同步时间。

空账户首次初始化沿用初始持仓基准；账户已有计划或历史观察后再同步新增股票时，因无法确认其历史纳入时间，持续持有对照会标为无效，避免将新增资产当成历史基准。同步不改变已有成交的配对收益。

新同步持仓的可卖数量为未知，监控默认关闭，核心下限和日终目标暂等于总股数，单次做 T 及临时增仓上限为 0。点击个股「核对」填写可卖、持仓边界、板块等内容，再启用该股与账户监控。同步不会核对账户资金，也不把批次买入日倒推为历史可卖库存或成交记录。

费用可以在成交明细中更正，原费用及原因保留审计。股数／价格登记错误首版不支持交易冲销，应暂停新计划并核对账户；不可通过删除信号抹掉实际成交。平台外数量或资金变化使持续持有对照失效时，权益差显示未知。

## 已实现的数据与交易约束

- 总持仓、可卖、当日买卖数量、核心下限、目标、券商冻结和平台预留分别维护；金额用 Decimal，数量为整数股。快照覆盖带版本及事件水位，未决委托存在时拒绝盲目覆盖。
- 先买后卖预留首笔资金及第二笔所需旧库存。先卖后买预留可卖和回补额外资金缺口；实际确认卖款继续预留回补，不要求卖出前准备完整回补款。
- 当日买入永不直接增加可卖。先买 200 再卖 200 后，总股数恢复，但原可卖 1000 只剩 800；卖出再买回也不恢复可卖。
- 每账户同股只允许建立一个未完成计划。迟到成交作为事实照录；若与后续计划冲突，保留事实和资源并要求核对。
- 幂等键、订单累计水位、拒单、部分成交、撤单未确认、手续费最低收费组、FIFO 两腿匹配均由事务账本处理。核对结果不等于券商已验证可执行。
- 首笔等待 5 个交易分钟后停止继续增加首笔；有效／未知委托的资源仍保留。第二笔时限从首笔实际成交起算，午休和休市不累计。超时、封板、资金或库存变化、数据过期均提示处理，不保证退出成交。

## 数据接入门槛

复用 QuoteService、现有分钟 Provider 路由、DepthService 和 SectorMonitorService，没有新增行情供应商。未知字段不得用接收时间、当前价、AI 或搜索结果填补。

| 数据 | 标准契约及缺失行为 |
| --- | --- |
| 股票／指数快照 | `symbol,last_price,prev_close,change_pct,timestamp`；timestamp 为真实市场 Unix 毫秒。服务补独立 `received_ts` 和 source，不替换原市场时间。 |
| 证券状态 | 快照或盘口明确提供 `trade_status=trading/suspended/delisted`。缺失为 unknown，暂停判断；不能因有价有量就推断可交易。 |
| 当日价格范围 | 快照提供 `limit_up_price,limit_down_price` 的实际价格，或由数据源明确标识 `price_limit_rule=standard` 允许复用已有日期化规则计算；未知时理论价只用于观察，暂停建计划。`no_price_limit=true` 及上市初期暂停建计划。 |
| 盘口 | 现有 depth5 规范的 `bid_prices,ask_prices,timestamp`；无真实盘口时间／报价时暂停执行判断。盘口与成交快照时效都须匹配。 |
| 1 分钟线 | 现有仓库契约 OHLC 元、volume 手、amount 元，适配为股；必须确认 datetime 表示开始还是结束。只使用已收盘、当日从 9:31 连续完整的分钟；午间和集合竞价不纳入。量额与 OHLC 不相容则暂停。 |
| 历史容量 | 本地仓库至少 20 个有效历史交易日，取日成交股数／240 的中位数作保守容量参照；不使用今天最终量。 |
| 市场环境 | 新鲜全市场和指数快照聚合已配置板块，至少 80% 覆盖并预热 5 分钟。`market_return_5m/sector_return_5m` 当前口径为日涨跌幅在 5 分钟内的变化，小数制，不是严格区间收益率。 |
| 交易日历 | 复用有来源证据的 2019-09-12 至 2026-12-31 交易日历。超覆盖范围暂停，须先更新日历。交易时段按北京时间，首次范围为连续竞价。 |

**现有数据源未必提供证券状态、当日价格范围及完整分钟语义。功能接入成功不代表这些字段已接通；此时页面应显示“数据不足／暂停判断”，不能宣称可实盘使用。** TickFlow 上游可选字段仅透传，未假设一定存在。自定义源需要在既有 realtime/depth5 规范结果中补充上述字段；数据授权、频率和字段含义须由接入方确认。选定分钟插件不可用时不跨源回退。

行情和盘口默认最大时延 10 秒，分钟最大 75 秒、收盘宽限 15 秒，人工账户／持仓核对 15 分钟有效。恢复后重新计算，旧触发不能直接复活。分钟每分钟一批，盘口与现有封单服务共享节流；权限容量不足的标的明确暂停，未完成计划优先。

## 策略与价格口径

实现位于 `backend/app/strategy/position_t.py`。两套候选都使用当日累计 `VWAP=Σamount/Σvolume_shares`、20 分钟 ATR、已经形成的支撑压力、最近 3 根完整分钟的转向确认以及成交量确认。代码返回逐条件通过／未通过证据，没有 AI 概率评分。

- 先买后卖：近期出现 VWAP 下方波动偏离，最近完整分钟恢复，支撑、成交量和趋势过滤通过，目标回到 VWAP 邻域。
- 先卖后买：近期出现 VWAP 上方偏离，最近完整分钟回落，压力、成交量和趋势过滤通过，目标回到 VWAP 邻域。
- 数据、市场方向、库存、核心持仓、资金、容量、价格、费用和风险预算是硬过滤。配置改变后以新版本重新校验；账户同日次数、累计量、冷却和隔夜仍占用的风险都计入。
- 开新计划的研发窗口为 10:00–11:15、13:05 至配置截止时间（默认 14:00）；第二笔独立跟踪。默认单次净价差至少 20 元且至少买入额 0.2%，单次风险 100 元、日风险 500 元、单股日次数 2、账户日次数 6、冷却 15 分钟、参与率 1%。这些仅是保守研发初值。
- `净价差=(卖价-买价)×匹配股数-双边佣金-税费-其他适用费用-未计入参考价的执行偏移`。最低佣金按订单收费组计一次；成交均价已经含执行偏移，实际收益不再重复扣滑点。条件净价差是情景值，不是统计期望或盈利承诺。

数量、价格单位和有效范围按板块检查。科创板普通限价单最低 200 股、递增 1 股、最多 10 万股；不能误用盘后固定价格交易的 100 万股上限。规则核验来源：[上交所 2026 交易规则发布页](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)、[深交所 2026 交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)、[北交所交易规则](https://www.bse.cn/jygl_list/200028217.html)。后续规则变更需更新日期化规则及测试。

## 复盘与保守回放

实时复盘分别展示已匹配净收益、未匹配数量、全部费用与当前权益。日期选择筛选计划，**不表示该日收盘估值**；没有新鲜估值价格或持续持有基准失效时不输出伪精确权益。手续费更正会重新分摊和匹配。

历史模拟只使用本功能实际运行后留存的首次观察证据：原始分钟、当时市场／板块环境、原始行情时间、接收与计算时间、账户和持仓快照。没有这些记录时拒绝回放，不用今天的成分股或事后行情补历史证据。每天首个完整窗口只作预热，不能提前交易或估值。快照迟到时按实际可用时间处理。

页面／HTTP 首版仅开放单交易日保守模拟，以首个已核对快照为起点，使用独立临时模拟账本，不代表真实账户历史收益。首笔最早在信号延迟后下一个可执行完整分钟模拟，两笔绝不在同根分钟按有利顺序完成。限制成交参与率、部分成交、封板不可成交和 T+1；首笔部分成交后保守停止剩余首笔；无收盘自动补齐。结果保留未完成计划、期末增量权益、回撤、完成率、费用拖累、单笔不利变化和样本数量。未做样本外检验，盈利概率和样本外表现显示未知。内核保留受控输入下最多 60 个交易日的跨日 T+1 测试能力，但未对外开放真实跨日历史回放。

首版尚无公司行动或外部资金流事件模型，因此不开放跨日 HTTP 回放；区间已知不一致会拒绝或使基准无效。缺少事件字段不等于已证实不存在事件。不可验证的历史区间不能用于收益验收。分钟模拟没有逐笔队列与成交保证。

## 技术位置、恢复与兼容

| 层 | 文件／职责 |
| --- | --- |
| 前端 | `frontend/src/custom/lots/`；复用现有路由注册、API 客户端、QueryKey、Modal、分时图。 |
| API | `backend/app/api/position_t.py`，前缀 `/api/position-t`；严格输入、版本冲突与错误响应，未开放券商下单。沿用登录会话认证，外部 Bearer Token 没有新增授权范围。 |
| 编排 | `services/position_t_service.py`，FastAPI lifespan 启停独立线程；候选与计划分离，恢复重验，outbox 站内去重。 |
| 行情 | `services/position_t_market.py`，只依赖现有 Provider／行情／仓库服务；不读取页面数据。 |
| 账本 | `services/position_t_store.py`，`data/user_data/position_t/ledger.sqlite3`；WAL、事务和事件审计、幂等、资源预留、费用匹配。 |
| 研究 | `strategy/position_t.py` 与 `backtest/position_t_replay.py`，确定性规则和独立模拟；AI 不参与风控或状态变更。 |

启动时使残留候选过期，保留真实成交、未完成敞口与预留。数据库写入失败回滚；站内提醒通过持久 outbox 重试、稳定事件 ID 去重；过期候选不补发。外部推送首版未新增接通。

SQLite 数据目录需要可写本地磁盘；部署沿用项目现有单实例进程保护。备份请停止服务后复制整个 `position_t` 目录，避免只拷贝活跃 WAL 中的主文件。旧 `/api/lots`、旧批次 JSON、paper 和行情 Parquet 不迁移不覆盖。回滚代码会停止新监控，不能据此撤销真实外部成交；需先人工处理已有计划。

前端扩展采用现有注册入口；main 生命周期及行情原始快照／盘口公开读取属于必要的核心改动。以后升级上游应重点复核这三个接入点与数据字段，而不是覆盖用户账本。

## 验证入口

后端测试：`test_position_t_{rules,store,replay,service,market,lots_sync}.py`；包含 T+1 零可卖、恢复总股数后可卖消耗、部分成交、并行资金、最低收费、断流、重复与乱序回报、撤单未确认、隔夜、费用更正、事务回滚、无未来数据和重启恢复，以及批次同步的合并、去重、版本冲突和旧仓保护。还需运行旧 `test_lots.py` 及行情／盘口／板块相关回归。

前端：`pnpm build`、持仓监控组件测试及扩展注册回归；桌面浅色／深色、窄屏和模态表单检查。界面检查使用明确模拟数据，不构成真实数据供应商或券商实盘验收。
