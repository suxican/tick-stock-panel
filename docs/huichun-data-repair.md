# 回春复权数据核验与修复

回春使用 `adj_factor` 中的单次除权比值 `ex_factor`，按生效日期累乘构建因果复权价格。
累计复权因子不能直接写入该字段。异常跳变会触发隔离，但通过跳变检查不代表事件完整、
日期正确或收益已核验。不能为了增加候选数量而关闭隔离或把异常值统一改成 1。

## 先形成可审核清单

按 `(symbol, trade_date)` 列出本地值、来源事件、分红送转配股成分、前一个交易日原始收盘价、
除权日原始收盘价、拟修正值及理由。日期使用北京时间，事件成分遵守每股口径；
同日多条成分先按数据源契约合并，再计算单次比值。前收盘缺失或有冲突时保留待核验。

优先核对交易所或公司公告，并用独立行情来源交叉检查。缓存中没有某条事件、数据源返回
空集、明细全部为空或因子很大，都不能单独证明应删除该键。来源失败和“已确认无事件”
必须区分。核对报告应记录来源时间、完整性限制及输入文件摘要；尚未确定的条目保留原状。

## 现有同步能力及边界

数据页“独立同步除权因子”对应 `POST /api/pipeline/adj-factor/run`，复用现有任务通道、
数据源路由和进度查询。服务从本地日线起点获取历史事件，对相同键以新值覆盖，随后刷新
复权视图、对受影响股票重算已有历史指标并使相关缓存失效。该入口不提供单条删除功能。

底层 `kline_sync._merge_adj_factor_store` 是合并更新：来源未返回的旧键继续保留。
因此重新同步可以更新同键错误值，不能保证清理误写事件。来源仍不正确时重复同步也不会
解决问题。研究用替代因子文件仅用于审计，其覆盖股票、时段和未解决事件可能不同，
不得直接覆盖业务复权表。

## 定向修复与回滚

需要删除或定向替换时，应先把审核后的增改删清单变成可审查的一次性修复方案；当前没有
通用的复权删除 API。按以下边界实施，不另建绕过数据仓库的页面写入路径：

1. 避开行情同步、指标计算等并发写入，沿用现有写任务互斥与行情暂停机制。备份完整原始
   复权文件、文件摘要和受影响股票列表，明确备份位置及恢复方法。
2. 应用前再次核对源文件摘要与审核清单一致。只处理列明的事件键，保留其他日期、股票、
   列和事件明细；结果须满足键唯一、日期有效、因子有限且大于零。使用既有原子写入工具，
   校验失败不得发布部分结果。
3. 在写入前确定受影响股票，覆盖新增、修改和删除事件。参考
   `daily_pipeline.run_adj_factor_sync` 的既有链路刷新 `adj_factor` 视图、重算这些股票的
   历史 enriched、刷新相关视图及缓存，并核对版本和前端查询失效。
   不要假设写完文件后再点同步就一定重算：此时同键值可能已相等，删除键也不会出现在
   同步返回的变更列表中。
4. 重新扫描受影响时段并刷新收益与研究记录，检查隔离数量、形态、图表、临界价及基准
   指纹变化。旧记录显示“基准变更”时保留该事实，不重写冻结指纹来伪装为同一份历史证据。
   无关股票与早于修正生效日的安全区间应保持一致。
5. 若发现错误，恢复备份的复权数据，并对同一受影响集合重新执行视图、指标及缓存更新。
   单独恢复文件或删除回春记录都不构成完整回滚。

完成记录应包含实际变更键、未解决条目、前后摘要、验证结果和回滚位置，不包含账号凭据。
本规程描述修复约束，不表示任何本地数据已经被修正，也不证明策略具有收益优势。
