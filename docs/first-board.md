# 首板模式工作台

`/first-board` 提供「今日盯盘、信号记录、效果验证、规则版本」四个标签页，复用现有行情仓库、市场环境、行业数据、监控通知和模拟盘。

## 使用流程

1. 准备股票及上证指数日线、市场环境历史和行业数据。盘中盯盘还需要可用的实时行情能力，并开启全局实时行情。
2. 在「规则版本」确认市场范围、三类形态和风险参数，保存后生效。默认不开启自动盯盘；开启后应用须保持运行。
3. 在「今日盯盘」查看候选及形态证据。候选由上一完成交易日建立，盘中使用当前有效行情确认状态。缺少必要数据时显示原因并停止买入提示。
4. 在「信号记录」按日期查看触发证据。监控中心支持「首板模式」规则，可选择事件、标的范围、冷却时间和通知渠道。
5. 如需模拟交易，先创建并关联现有模拟账户，再人工提交模拟买入或卖出。不会自动提交模拟委托或向券商下单。建议使用专用账户；账户统计包含其全部交易。
6. 在「效果验证」选择已完成的历史日期，运行观察研究或规则比较。比较结果不会自动替换当前规则。

## 规则与数据口径

默认范围为沪深主板、创业板及科创板的非风险警示股票，不含北交所、B 股、ETF 和指数；也可选择仅沪深主板。三类形态为平台突破、趋势加速、超跌反弹。定量阈值是可验证的实验参数。

| 参数 | 默认值 |
| --- | --- |
| 首板排除窗口 | 最近 10 个实际交易日没有收盘涨停 |
| 最少历史 | 60 个交易日 |
| 临近涨停确认 | 突破形态参考高点、涨幅至少 5%、距涨停价最多 3% |
| 流动性 | 换手率 2%–30%，成交额至少 5000 万元 |
| 行情时效 | 同一北京时间交易日，最长 30 秒 |
| 市场环境 | 强势、偏强、震荡 |
| 行业联动 | 默认要求完整行业成员报价覆盖 ≥80%、至少 3 只有效成员、2 只涨幅达 5%、平均涨幅至少 1% |
| 仓位上限 | 最多 4 只；单股 25%、同行业 50%、总仓位 50% |
| 次日退出提示 | 10:30 或成本下跌 3%，仍需人工确认 |

形态和收益观察使用复权价；涨停判断、估值及委托使用原价。涨跌幅是小数（`0.05=5%`），enriched 换手率是百分数值（`2=2%`），成交额单位为元。

新版流水线的 `limit_up_price` 是交易所生效价减 `0.005` 后的判定阈值。盘中直接消费该列，还原展示价格时只补回一次容差。缺列、空值、非有限值及无价格限制日不猜测涨停价；不依赖已移除的 `limit_up` 信号列。历史研究仅在输入完全没有判定价列时使用旧窄表兼容计算，显式空值仍保持无效；创业板历史按改革日期区分规则。

观察窗口是北京时间 09:30–11:30、13:00–14:57（不含结束时刻）。过期、未来或重复行情、缺失原价高点、历史缺口、无效环境均阻止买入提示。行业横截面联动不能代表完整题材主线，快照高点不能证明回封先后，涨停价观察不代表可成交。

模拟委托复用原有撮合、手续费、滑点和 T+1 规则；提交时再次检查事件、版本、行情、预算和可卖量。开启涨跌停排队的账户被工作台拒绝。科创板买入至少 200 股，沿用现有百股步长；689 存托凭证可观察和研究，但暂不通过工作台提交模拟委托。

退出数量只包含能够明确归属首板、位于账户先进先出队首的连续可卖批次，并扣除待成交卖单占用。同股同日混合买入来源时，现有账本无法区分剩余批次归属，因此不生成该日期的退出提示，也不跳过较早手工批次去卖出较晚首板批次。

止损成本从成交台账按 FIFO 重建，计入实际买入费用、已卖出数量和公司行动，再扣除待卖订单占用的队首批次；不使用同股手工加仓后的账户整体均价。重建结果须与现有持仓批次核对一致，成本或来源无法确认时停止该标的退出提示，不改写原账本。

行业确认的覆盖率分母为当前完整行业映射，缺失、重复、无效或过期报价不缩小分母。裸代码通过股票维表唯一映射后与完整代码去重；无法唯一解析成员的行业不参与确认。返回的 `sector_confirmation.member_count/count/coverage` 分别表示完整成员数、有效报价数和小数制覆盖率，原因文案同时展示覆盖情况。行业二级代理仍不代表真实题材主线。

## 研究边界

### 板块联动重点观察（首期）

「今日盯盘」新增板块联动列，可筛选强势板块、领涨带动、同板块双条件，或按关注优先级升序／降序排列；第三次点击恢复默认顺序。未知结果始终置底。展开「联动依据」查看来源、排名、覆盖、首次观测触板时间及分钟证据。标签不改变形态状态、原有行业确认、买入门槛或模拟权限，下跌股票仍可能属于历史形态观察池。

`attention-v1` 的固定实验口径如下；这些门槛尚未证明能提高次日溢价。

| 证据 | 首期定义 |
| --- | --- |
| 强势板块 S | 同来源、同分类字段内排名前 20%（同值并列）；至少 5 只有效成员且报价覆盖 ≥80%；平均涨幅 >0 且高于该来源分类覆盖股票的去重平均；上涨家数占比 ≥60% |
| 领涨触板 | 同一行业或概念中，除候选自身外，系统已观测到触及涨停判定价、且本次新鲜报价仍在涨停价的成员；优先最早被观测者 |
| 分时走强 | 使用已完成的 6 个一分钟收盘端点计算近 5 分钟收益；收益和价格斜率为正，末价高于当日累计量额均价，窗口收盘价最大回撤 ≤1% |
| 领涨带动 F | 候选当前未触板；整个 5 分钟窗口严格晚于领涨股首次被系统观测触板，并同时满足分时走强 |
| 同板块双条件 | 至少一个相同板块同时满足 S 和 F；两个不同概念分别命中不合并为双条件 |

板块均值不是全市场指数收益。成员继承现有行业／概念目录，保留来源和分类字段身份，优先行业二级，过滤属性概念及超过 300 个成员的过宽分组；按首板市场范围排除风险警示股票。裸代码只通过股票维表映射；含无法唯一映射成员的分组整体排除并说明。成员分母不随行情缺失缩小。

显式声明 `market_level` 的扩展数据是市场报告或事件表，即使包含概念字段也不作为股票成分来源；其更新不触发成分缓存失效。真正成分源的缺键或读取失败仍会停止联动计算，避免用不完整目录进行排名。

“首次观测触板”不是交易所首封时间，也不证明封单稳定；开板后撤销当前领涨带动，重启后重新积累先后证据。强势、联动、分时采用 `true/false/null`，数据不足不当作未满足。行情过期、暂停盯盘、非连续竞价或快照失败后清除当前正向标记，仍可查看最近观测证据。

分钟输入只批量读取当日本地分区，须有已确认原价基准和可用分钟能力；量为手、额为元。新写入的 TickFlow 当日全量修复轮／增量轮附带逐行 `minute_price_basis=raw` 和 `minute_time_grid=auction_end` 证据；读取及分区合并保留这些字段。原价证据必须覆盖该股票截至计算时点的全部已完成分钟，新增尾部记录不能替旧记录证明口径。缺少逐行证据的旧分区仍须通过已有原价迁移标记确认，且读取未发生复权投影；显式未知或非原价声明不由迁移标记覆盖。不会据当前数据源设置推断存量来源，也不会自动迁移历史或创建标记。

合并时，只有原本完全没有价格基准字段的旧分区，才可凭既有迁移标记保留原价证据；旧字段中的空值不补，新输入未声明口径时也不继承被覆盖记录的证据。

均价要求从当日开盘开始完整，午后不能只取下午数据。未声明时间网格时保留 09:30／13:00 或 09:31／13:01 两种一致的 240 根序列；显式 `auction_end` 支持独立的 09:30 开盘点加 09:31–11:30、13:01–15:00 的 241 点序列，开盘量额计入当日均价。网格声明不代表精确交易所完结时刻，仍仅使用时间戳严格早于当前分钟的数据；不挪动标签、不补缺根。缺基准、混合口径、量额不符、重复、迟到或缺根时显示原因；首板读取本身不触发远程补数。

### 前向样本积累

启用有效盘中盯盘后，在每个 5 分钟锚点所在分钟采集一次完整候选，包含正例、负例及未知；按股票去重，同时保留全部形态与当时交易权限。显示「今日采样时点」指当前规则版本在当日已记录的时点数量，不是股票数量。错过锚点或计算跨过该分钟不补采，真实采样时间与开始计算时间分别保存。

样本保存规则、成分版本、报价覆盖、市场环境、分钟基准及判断原因。成分文件和样本以不可覆盖的 gzip JSON 发布；相同日／规则／时点重启不重复，坏文件保留并报错。读取与写盘在现有首板工作线程内，研究写盘不持有页面快照锁；研究失败不改变既有买入门槛，通知失败仍尝试保存研究分母。同一批本地分钟复用计算结果，分区更新或候选／时间窗口改变后重算。

首期只建立标注和可验证数据。现有「效果验证」仍是下面的日线观察研究，尚未增加四组次日溢价比较、成交收益或自动调参。后续比较应区分 S0F0、S1F0、S0F1、S1F1、未知及跨板块混合情况，以当时样本及成分为准，不能用今日成分倒填历史，也不能只比较最终涨停的幸存股票。

### 日线观察研究

每个 T 日仅使用 T-1 及更早日线建立候选，再观察 T 日触板、收盘封板及 T 收盘至下一交易日的复权价格变化。这些收益不扣交易成本、不假设买入成交，不是交易胜率。

单次研究最多 366 个自然日。缺少下一交易日数据时保留缺失；不跳过缺口或填零。三种形态可能重叠，同股同日按形态分别计样本，同时提供股票日数量和数据覆盖说明。

比较按时间前 70% 训练、后 30% 留出验证；只用训练数据选择变体，并排除跨分割边界的收益标签。至少需要 30 个训练和 10 个验证有效样本；缺日历、覆盖不足或留出结果未改善时不推荐修改。历史名称、退市样本与行业历史归属仍受本地数据覆盖限制。

## 存储与兼容

运行数据位于 `DATA_DIR/user_data/first_board/`：

- `config.json`：当前配置和历史规则版本；保存检查版本冲突。
- `events/YYYY-MM-DD.json`：当天状态、去重信息和证据。
- `research/*.json`：观察研究、规则比较与数据指纹。
- `observations/memberships/<version>.json.gz`：前向采样使用的成分版本和首次保存时间。
- `observations/YYYY-MM-DD/<revision>/HHMM.json.gz`：当时完整候选、实际观测时间、锚点和数据口径。不会修改旧事件文件或回填历史。

沿用旧版 schema 1 和目录。日内文件新增可选 `pending_alert_ids`：发布失败保留原事件 ID，当日后续行情或重启后可重试；过期、旧版本、禁用及已被新状态替代的事件不重发。旧文件缺字段不会重放全部历史。通知成功到本地确认之间若进程崩溃，可能以同一 ID 重试，由监控规则接收端去重。

配置和日内证据原子写入，损坏文件保留并停止相关处理。研究一次只运行一个任务。模拟盘沿用原账本，无第二套资金存储。代码迁移不搬动或覆盖用户已有运行数据。

API 前缀 `/api/first-board`：`GET/PUT /config`、`GET /versions`、`GET /snapshot`、`POST /refresh`、`GET /events?day=YYYY-MM-DD`、`POST /research`、`POST /compare`、`GET /research-runs`、`POST /paper-order`。
