# 超短线博弈研究计划

“超短线博弈”使用已经同步到本地的盘后行情，形成未来 1–3 个交易日的条件计划：市场趋势、周期与情绪，行为假设，最多 3 个板块和 5 只候选，以及触发、失效和仓位上限。当前规则版本为 `1.0.0`，所有报告均标记为研究阶段。

本功能尚未完成样本外收益验证，没有经过校准的胜率或情景概率。条件成立不等于已经成交，仓位预算也不保证最大损失。它不连接券商，不自动下单，不读取账户余额和持仓。

## 入口与使用

从侧栏打开 **超短线博弈**，页面路径为 `/market-game`。

1. 先通过系统已有的数据源与同步功能准备股票日线、核心指数日线、股票基础资料及行业或概念映射。
2. 保持日期留空，或点击“最新盘后”，生成一份当前观察计划；也可以指定日期进行历史研究。
3. 按需调整“风险参数”，点击“生成盘后计划”。生成成功后自动归档，不覆盖旧报告。
4. 先读数据边界、条件仓位和失效条件，再查看板块与个股清单。没有合格候选时保持空名单和零新增仓位。
5. 从“历史计划”读取已归档报告；点击“查看后续表现”读取其后续收盘观察。AI 解读为可选功能。

点击候选名称打开的是系统现有个股详情，展示当前数据，不是报告时点的历史回放。

## 本地数据与日期边界

规则分析只读本地标准化数据，不主动请求外部行情、不触发补数或全市场同步。缺少数据时，应先在现有同步入口处理，再重新生成报告。股票基础资料缺失、行业概念未同步或核心指数数据不完整，都可能影响结果。

计算最多读取 80 个本地已观测交易日期。股票均线、收益和 ATR 复用既有指标流水线，涨跌停复用统一价格限制规则；参考买卖价格使用目标日原始价格标尺。窗口使用本地观测日期，独立交易日历及历史停牌覆盖尚未得到完整核验，不能将这些日期简单替换成自然日。

| 模式 | 行情与截止时间 | 当前名称、板块与交易资格 | 输出边界 |
| --- | --- | --- | --- |
| 最新盘后，日期留空 | 北京时间 15:10 前最多使用前一自然日及之前的本地日线；之后可使用当日已完成的收盘记录。`as_of` 保留实际行情日期，`cutoff` 是本次生成时点 | 允许使用本次读取的当前资料，标记为 `current_observation` | 有充分证据时可形成前瞻观察候选；节假日也不会把旧行情改标成当天行情 |
| 显式指定日期 | 截止指定日北京时间 15:00；无该日数据直接报错，不自动替换日期。指定当天须等到 15:10 后 | 不使用当前板块映射，历史交易资格标记为未核验 | 只做历史研究；缺少时点数据（PIT）时不生成可交易候选 |

这里的 `research_only=true` 表示规则仍处于研究阶段，并不自动清空最新模式的候选。显式历史模式通过禁用未经核验的当时交易资格与板块归属限制候选，不能把最新模式重新生成的报告当成“当时已经知道”的预测。

日线中有行情时间戳时，会检查其日期、收盘时段和截止时间。缺少首次公开时间的历史记录仍保留 `available_at=null`，不虚构可获得时间，也不宣称已经具备完整的历史信息集。

## 从书籍到可核对的规则

依据[《股市博弈论》笔记](策略/股市博弈论/股市博弈论-杨新宇-核心内容提取.md)与[续篇笔记](策略/股市博弈论/股市博弈论续篇-核心观点与阅读笔记.md)，分析顺序是：观察市场状态，提出行为假设，写出确认和反证条件，再分配风险。

“站在散户对立面”在这里指识别追涨、恐慌卖出和亏损后改变交易理由等可能付出代价的行为。系统不会机械地“大家买就卖、大家卖就买”，也不把量价变化直接解释为某个主力的确定意图。每项假设都展示事实、解释、替代解释、确认条件和失效条件。

首版包含三种模式：

| 模式 | 必要证据 | 对应行为 |
| --- | --- | --- |
| 恐慌后的首次修复 `panic_repair` | 前日广度与中位收益显著偏弱；本日广度及收益改善，并有跌停收敛或昨日涨停溢价改善的独立支持 | 只观察得到板块与价格承接确认的股票，不因跌幅大就抄底 |
| 主线趋势中的分歧修复 `trend_pullback` | 指数与市场广度支持上行趋势；短期出现分歧，亏钱效应仍受控；候选所在板块相对强势 | 等候触发区间与板块确认，不追入已经超过上限的高开加速 |
| 一致追涨后的兑现风险 `crowded_exit` | 高上涨占比与放量之后，同时出现封板、溢价或市场广度弱化 | 暂停新增仓位，复核原有退出条件；高热度本身不等于见顶 |

趋势、周期、情绪和拥挤程度分别显示。周期可为 **冰点、修复、启动、主升、高潮、退潮**，证据不足时显示 **待确认**。周期主要由本日、前日及截止日前计算的指标判断，不调用看完未来走势才得到的阶段标签；阶段允许跳转，不假设固定循环天数。模式名称不代替周期名称，处于主升阶段也不保证存在合格的分歧入场机会。

## 板块与候选怎样产生

当前本地行业、概念映射支持一只股票的多个归属。按各组可用成员计算当日平均收益、上涨占比和 5 日持续性，优先保留相对强势组；一只股票最终只进入一次清单，选择它所属的最强有效板块。

首版排除少于 3 只或多于 600 只可用成员的组。选取最多 3 组时，成员交并比大于 0.8 的近重复组只保留一组；入选组交并比至少 0.5，或较小组至少 70% 的成员与另一组重合时，共用一份板块风险预算。这里衡量的是成员重叠，不代表已经估计了收益相关系数。

候选必须通过交易资格、非 ST、非涨跌停、非一字价格、成交额及历史完整性过滤。首版要求上市至少 60 个**自然日**、至少 21 个连续有效的**观测交易日**，并满足对应模式的均线、收益、收盘位置和回撤条件。数据缺失按不可计算处理，不以零值补齐。

候选展示参考收盘价、确认参考区间、失效参考价、压力损失和最长 3 个交易日的持有计划。触发日计为持有第 1 日；只在计划的下一交易日观察入场，未触发的计划不会在之后自动重新启用。除权等改变价格标尺的事件发生后，需要重新生成计划。

## 风险参数与仓位含义

页面按百分比展示；API 中所有收益、比例和仓位均使用小数，金额为人民币元。

| 参数 | 默认值 | 可配置范围 |
| --- | --- | --- |
| 总仓位上限 `total_cap` | 50% | 0–100% |
| 单股上限 `single_cap` | 15% | 0–100% |
| 板块上限 `sector_cap` | 25% | 0–100% |
| 单笔风险预算 `risk_per_trade` | 0.5% | 0.01–2% |
| 最低日成交额 `min_amount` | 1 亿元 | 0.1–1,000 亿元 |
| 候选数量 `max_candidates` | 5 | 1–5，只接受整数 |

最终仓位还要接受规则限制：恐慌修复最多 20%，趋势分歧最多 40%；输入有限时进一步压至 10%。上述值再与用户总上限取较小值。一致兑现风险成立、数据不可用、没有入场模式或没有合格候选时，新增仓位为零。

单股额度同时受单股上限、剩余组合额度、所属板块或重叠组剩余额度，以及“单笔风险预算 ÷ 压力损失比例”约束。压力损失取 6%、两倍 ATR 比例、“触发上沿至失效价距离加 3% 隔夜缓冲”三者的最大值，再加 0.3% 成本假设。所有这些阈值都是研究初始参数，并非已验证的最优值。

条件仓位下限始终为零，上限是本期模型可能新增的敞口，不是要求买满的目标，更不是结合真实账户计算后的买卖数量。页面不读取已有持仓；同一股票、板块已有的风险仍需合并考虑。实际退出受到 T+1、停牌、涨跌停、跳空和流动性约束，失效价不保证能够成交，实际损失可能超过压力预算。

## 证据、归档与后续观察

报告保留以下时间和版本信息：

- `as_of`：股票行情归属日期。
- `cutoff`：本次分析的信息截止时间。
- `created_at`：报告实际生成时间。
- `observed_at`：证据对应的行情或本次观察时点。
- `available_at`：已知的可获得时间；未知时保留空值。
- `input_version`：输入快照指纹；`rule_version`：规则版本。

每次成功生成都创建独立报告编号。数据保存到应用配置的数据目录下：

```text
<data_dir>/user_data/market_game/
  mg_<32位十六进制编号>.json
  mg_<编号>.explanation.json
  mg_<编号>.evaluation.json
```

主报告文件保存原报告、输入快照及当次风险配置，生成后不被重新计算覆盖。AI 解读和后续观察使用独立附属文件；观察更新不改写预测。列表默认显示最近 200 份，较早报告仍保留，可按编号读取；当前没有自动删除策略或删除接口。

后续观察只读取已同步的本地行情。它以报告行情日的前复权收盘价为基准，对照实际截止时间之后的最多 3 个已观测市场日期，缺少日期或个股数据时显示等待或缺失。收益来自同次读取的复权序列，不直接用原始报价跨除权相除。

基准日、后续股票与指数记录还必须有同日收盘后的原始行情时间证据，且原始收盘价须与复权记录中的对应原始价一致。缺少时间戳、仅有盘中快照、存在重复或缓存尚未更新时显示“无法核验”，不把缺值当作零收益；基准证据不得晚于报告截止时间。

**观察名单涨跌幅不是策略回测收益。** 日线不能确定触发价和退出价出现的先后，首版不认定入场已经发生，不模拟成交、排队或退出，也不计算策略胜率。完整交易日历、执行回测和样本外收益验证仍是后续工作。

## AI 解读的边界

点击“生成 AI 解读”会使用系统已经配置的 AI 服务。规则分析本身不依赖 AI，也不进行外部行情同步；AI 服务失败不会改变冻结计划。

模型只能返回两个字段：已有假设编号 `hypothesis_ids`，以及 `focus` 中的 `behavior`、`alternative`、`confirmation`、`invalidation` 枚举。服务端拒绝未知编号、重复值、多余字段和自由文本，再按所选重点引用冻结报告中的事实、解释与条件。

AI 不能新增股票、修改价格或仓位，也不能自由生成交易建议。可见正文来自既有报告；模型只选择复核重点及顺序。已保存解读会被复用，不重写主报告。

## 数据不足时的行为

| 状态 | 典型原因 | 行为 |
| --- | --- | --- |
| `ready`，输入可用 | 基础覆盖达到本版要求 | 仍需逐项检查模式、候选和缺失指标，不保证存在仓位 |
| `limited`，数据有限 | 历史不足 25 个观测日、股票覆盖不足 95%，或核心指数覆盖不足四只 | 保留可核对内容，市场仓位上限最多 10%；不补猜缺项 |
| `unavailable`，暂不可分析 | 当日有效记录为空、股票覆盖不足 50%、最新行情距今超过 14 个自然日，或核心指数已有更晚收盘记录而股票未同步 | 不生成新增仓位与候选 |
| 请求失败 | 无本地日线、指定日没有记录、未来日期、指定当天尚未完成收盘确认 | 返回错误，不替换日期或偷偷同步 |

重复、异常、停牌零成交或不能确认为收盘的记录会被剔除。缺少板块映射时不为个股猜题材；历史归属缺乏时点核验时不生成可交易候选。报告中的完整限制说明应与数值一起阅读。

## API 与维护

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/market-game/analyze` | 生成并保存报告；请求为 `{"as_of": null, "risk": {...}}`，省略字段使用默认值 |
| `GET /api/market-game/reports` | 读取报告摘要列表，返回 `{"reports": [...]}` |
| `GET /api/market-game/reports/{report_id}` | 读取冻结报告 |
| `GET /api/market-game/reports/{report_id}/evaluation` | 读取后续观察并更新独立观察文件 |
| `POST /api/market-game/reports/{report_id}/explain` | 生成或复用受限 AI 解读，返回 `{"content": "..."}` |

并发生成中的再次请求返回 `409`；服务未就绪或临时故障返回 `503`；报告不存在返回 `404`。无效数据、日期或报告返回 `400`，请求模型不符合约束时由 FastAPI 返回 `422`。接口不承诺按日自动运行。

前端通过 `frontend/src/custom/market-game/extension.tsx` 注册页面与导航；后端通过 `backend/app/custom/market_game.py` 注册独立路由。扩展 ID 均为 `market-game.workbench`，契约版本为 1。规则、快照、报告存储与后续观察均位于独立服务模块，没有继承或替换核心策略、回测引擎。

当前注册机制没有专用的功能开关。需要暂时禁用时，在保留文件的前提下，将前端注册入口改为不匹配 `../custom/*/extension.tsx` 的文件名并重新构建前端；将后端注册模块改为以下划线开头的模块名，例如 `_market_game.py`，再重启后端。后端加载器会跳过这类模块。两端都停用后，页面与接口不再注册；仅隐藏导航不等于停用接口。

恢复原注册入口并重新构建、重启即可恢复功能。回退功能代码不需要迁移或删除已保存报告；主报告读取只接受已支持的 `schema_version`，不应通过覆盖旧文件处理版本变化。归档目录属于用户数据，应与应用数据一起备份，不提交到 Git。
