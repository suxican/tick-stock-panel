# 猫爪数据对接深度规划（按专业版设计）

> 依据：阶段 0 实测（`接口可用性与口径核对表.md`，2026-11-12）、猫爪官网接口目录与定价页（2026-11-12 抓取）、本仓库现有代码。
> 当前 Key 为体验版：每个高频接口每天限 100 次，`stock_ex_rights` 返回 403。本文能力按专业版规划，凡未实测的地方都标注了「未测」。

---

## 0. 结论摘要

1. **项目价值会显著提升，但提升主要来自「短线特色数据」，不是基础行情。**
   - 基础行情（日K、实时、分钟）已有 TickFlow、fuyao、tdxquant 覆盖，猫爪在这块只多了一个备选源。
   - 真正的增量有四类：
     - 2017 年起的**涨跌停池明细**：首封、末封时间，开板次数，封单额；
     - 09:15 起的**集合竞价全套**；
     - **题材库、精选板块、板块原因**；
     - **龙虎榜、游资、主力净额**等资金数据。
   - 这四类正好对应情绪周期、首板、短线博弈三个核心功能的数据缺口。
2. **建议采用「新增能力默认走猫爪、基础能力保持现状」的混合路由。**
   - 日K、除权因子、实时、分钟等存量能力暂不改默认源，猫爪作为候选和兜底。
   - 涨停池、竞价、题材、权威涨跌停价等新能力默认走猫爪，本地推算或其它源作为兜底。
3. **兜底要新建，不能只靠现有路由。**
   - 现状是每个能力只选一个源，运行时失败不会自动切换。
   - 需要新增按能力配置的**兜底链**，并配套健康熔断、切换粒度、来源标记三件事（第 5 节）。
4. **最先做的三件事（P0）**：
   1. `pricelimit` 作为权威涨跌停价；
   2. `limit_pool` 历史回填加每日归档；
   3. 题材成分每日快照归档。
   第 3 项越早开始，历史积累越多：猫爪的成分只提供当前快照，历史无法补拉。

- Key 不落盘、不打印；
- 不提交 `data/`；
- 猫爪字段不直接穿透到业务层，统一先转为本地契约（单位、百分数或小数、原价或复权、北京时间）。

## 2. 现状盘点：核心功能的数据来源与缺口

| 功能 | 现有数据来源 | 主要缺口 |
|---|---|---|
| **情绪周期 / 主线**（`regime_builder`、`market_phase`、`market_mainline`） | enriched 日线推算涨停、连板、晋级；`ext_gn_ths` 概念成分（2026-07 起留存的当前快照） | ① 只有收盘口径，**炸板次数、首封时间、封单强度**没有历史；② 概念成分用当前快照回看历史，有成分前视偏差；③ 没有板块原因和题材归因 |
| **首板**（`first_board_*`） | 实时快照；分钟数据；五档封单（`depth_service`，依赖 depth5 路由）；本地「首次观测触板」 | ① 触板时间是本地观测，**不是交易所首封时间**；② 封单依赖 depth5 轮询（tdxquant、TickFlow Pro），没有兜底；③ 没有竞价数据：开盘表现只能事后看；④ 题材人气只来自 zzshare 首页 |
| **回春**（`huichun_*`） | 本地日线、交易日历；涨跌停按本地规则推算 | ① 除权结算依据不足时结果留空；② 涨跌停规则缺少 S 股、新股、除权参考价；③ 历史 ST、停牌靠当前快照推断；④ 分钟成交容量受限于分钟历史深度 |
| **短线博弈**（`market_game_*`） | zzshare 情绪日报；fuyao 龙虎榜（**单一来源**）；本地分钟资金代理；Yahoo 外围 | ① 龙虎榜只有 fuyao；② 资金行为只能用分钟量价代理，**不能识别主力和游资**；③ 没有逐笔，算法交易身份标为「未验证」；④ 外围只有 Yahoo 一个源 |
| **全局** | 能力路由单选；`quote_service` 明确不做跨源回退 | **任何主源失效时只能人工切换** |

## 3. 接口清单（按领域）

图例：
- **形态**：
  - R = 已有路由能力，猫爪作为候选或兜底；
  - R+ = 新增路由能力，多源可替换；
  - E = 猫爪专有数据集（参照 fuyao 龙虎榜模式）；
  - X = 只做旁证或对账。
- **优先级**：
  - P0 = 第一批；
  - P1 = 核心功能增强；
  - P2 = 扩展；
  - P3 = 暂不接。
- **历史**：括号里是阶段 0 实测的起点，未测的标注「未测」。

## 4. 对核心功能的具体提升

### 4.1 情绪周期 / 主线

| 提升点 | 用到的接口 | 现状 → 接入后 | 口径边界 |
|---|---|---|---|
| 炸板率、封板率的历史序列 | `limit_pool`（2017 起） | 只有收盘涨停 → 盘中触板、炸板、开板次数完整回溯约 9 年 | 猫爪 `type` 是**收盘集合竞价前**的状态，约 1% 尾盘回封股会显示为炸板，最终状态需用收盘价等于涨停价复核 |

## 5. 兜底架构：接入猫爪不影响现有源和未来新源

### 5.1 原则

1. **业务层只认本地契约，不认厂商。** 每个数据集先定义源中立的 schema（单位、口径、时区、`source` 列），猫爪、fuyao、zzshare、本地推算各写一个适配器。
2. **路由矩阵是唯一入口。** 新能力全部注册到 `CAPABILITY_REGISTRY`，不在业务代码里写死 `get_provider("meoz")`（现有 fuyao 龙虎榜这种写死的方式逐步迁走）。
3. **失效时自动沿兜底链切换，但不在同一份数据里混用多个源。**
4. **本地推算永远是最后一层。** 能从 enriched 推算的（涨停池、涨跌停价、情绪统计）都保留本地实现。
5. **新源零侵入。** 新插件只需在 `plugin.yaml` 的 `datasets` 声明能力并实现适配器，就会自动进入候选和兜底链。

### 5.2 能力注册：三种接入形态

| 形态 | 做法 | 例子 |
|---|---|---|
| R：已有能力 | `plugin.yaml` 的 `datasets` 加声明，实现对应 provider 方法 | `depth5`（猫爪 `tick`）、`overseas`（`global_index`）、`financial` |
| R+：新增能力 | `CAPABILITY_REGISTRY` 新增条目，同时定义源中立 schema、本地推算兜底和设置页卡片 | `price_limits`、`limit_events`、`auction`、`theme_membership`、`st_history`、`corporate_actions`、`dragon_tiger`、`index_daily` |
| E：专有数据集 | 只有猫爪有、没有替代源：作为猫爪插件的扩展数据集，走 `ext_data` 归档；页面在缺失时显示「数据源未配置」 | `auc_kp`、`theme_reason`、`hotstock`、`fundflow_kp`、`point-monitor` |

> R+ 能力的 `tf_tier` 为 `None`（TickFlow 不提供），候选来自插件声明，另外固定追加一个 `local` 候选（本地推算）。

### 5.3 兜底链（新增机制）

**配置**：
- 在现有的 `<field>` 单选之外，新增 `<field>_fallbacks: [源, ...]`。
- 默认值由注册表给出，例如：
  - `price_limits`: `[meoz, local]`
  - `depth5`: `[tdxquant, tickflow, meoz]`
  - `overseas`: `[yahoo_overseas, meoz]`
  - `dragon_tiger`: `[fuyao, meoz]`
- 用户可以在设置页调整顺序。
- 生效源等于链上第一个「健康且在候选中」的源。

**健康判定（熔断）**：

| 失败类型 | 处理 |
|---|---|
| 401/403（Key 失效或权限不足） | 立即熔断该源的**对应接口**，直到 Key 变更或人工重试 |
| 429 或配额耗尽 | 熔断到次日 00:00（北京时间） |
| 超时或 5xx | 连续 N 次（建议 3 次）后熔断 5 分钟，再半开探测 |
| 返回截断（`MeozTruncatedError`） | 不算源失效，按参数拆分重试 |
| 数据异常（空表、日期不符、校验失败） | 当轮视为失败并走兜底，不写入 |

**切换粒度（避免口径混杂）**：

| 能力 | 切换粒度 | 原因 |
|---|---|---|
| 实时快照 | 整轮 | 同一轮内不能混用多个源 |
| depth5 | 整轮，并标记 `source` | 现有「depth5 不跨源回退」改为「轮内不跨源、轮间可切换」 |
| 日K、除权因子 | **整个交易日** | 同一天的数据只能来自一个源，避免复权基准不一致 |
| 分钟 | 单股单日 | 一只股票一天的分钟只来自一个源 |
| 涨停池、竞价、龙虎榜 | 单日 | 同一天的数据只来自一个源 |
| 涨跌停价 | 单日 | 猫爪失败时整日回退本地推算，并标记 `source=local` |

**可见性**：
- 能力矩阵新增 `active_source`、`degraded`、`fallback_reason`；
- 设置页卡片显示「当前由 X 兜底：原因」；
- 落盘数据带 `source` 列，事后可以按来源统计。

**改动面**：
- 集中在 `data_providers/capabilities.py`（矩阵和门禁）和一个新的 `routing_health` 模块。
- 各服务的取数入口逐步从 `get_provider(当前偏好)` 改为 `resolve_chain(cap)`。
- 先改新能力；存量能力（实时、日K）放到最后一个阶段，单独评审（属于高冲突热点）。

### 5.4 默认路由建议

| 能力 | 建议默认 | 兜底链 | 理由 |
|---|---|---|---|
| 日K、除权因子、实时、分钟、全量分钟 | **保持现状**（TickFlow 等） | 加入猫爪 | 存量稳定；猫爪分钟价格口径官方未写明 |
| depth5 | 保持现状 | 加入猫爪 `tick` | 盘中刷新延迟和批量上限**未测** |
| `price_limits` | **猫爪** | 本地 | 交易所口径更准；本地作为兜底 |
| `limit_events`、`auction`、`theme_membership`、`st_history`、`corporate_actions` | **猫爪** | 本地推算或其它源 | 新能力，猫爪覆盖最全 |
| `dragon_tiger` | fuyao（保持） | 加入猫爪 | 保持现有结果稳定，猫爪先作为兜底和交叉校验 |
| `overseas` | Yahoo（保持） | 加入猫爪 | 猫爪没有盘中数据 |
| 境内指数日线 | 保持现状 | 加入猫爪 | 深市指数成交量不可靠 |
| `financial` | 保持现状 | 加入猫爪 | 未测 |

**结论**：猫爪作为「特色数据默认源 + 存量能力兜底源」，不替换现有基础源。等兜底链运行稳定、口径对账通过后，再按能力逐个评估是否改默认。

## 8. 风险与口径边界

1. **短历史与快照**：
   - 成分、精选股票池只有当前快照；
   - 异动、热搜、竞价涨停、板块原因只有约 1 年或更短。
   - 这些只能从接入日起积累，**不能用来做长回测结论**。
2. **涨停池状态口径**：`type` 是收盘竞价前的状态，最终涨停必须用收盘价等于涨停价复核（本地已有）。
3. **单位陷阱**：
   - `indexdaily` 历史行成交额为千元、最新行为元；
   - `pct_chg` 是百分数；
   - 异动接口的数值字段是字符串；
   - 时间戳为毫秒。
   - 这些全部在适配器里归一，并配单测。
4. **厂商模型**：情绪周期、主力净额、ddx 都是厂商算法，只作为旁证或展示，不进入阶段判定的硬规则（除非离线验证通过）。
5. **单一厂商依赖**：E 类专有数据没有替代源，猫爪失效时对应功能只能降级展示。这就是 R+ 必须保留本地推算的原因。
6. **配额**：两站共享 10 万次。兜底接管实时和 depth5 时消耗明显，需要配额告警。
7. **合规**：Key 只存 `secrets.json` 或环境变量；数据只供本地研究使用，遵守猫爪服务条款（未核实是否允许二次分发，暂不对外提供原始数据）。

## 11. 持仓提醒：【持仓做T】与【持仓分析与计划】的提升分析

### 11.1 现状：两个功能卡在哪里

两个功能的设计原则一致：**未知不当作零，数据不足就暂停或限制采纳**。所以它们现在的主要问题不是算错，而是**因数据不足暂停太多，或证据不完整**。

| | ⑤ 研究失效条件和风险只能靠人工填写，没有事件提醒（财报、解禁、监管） | |

### 11.2 持仓做T：可接入的猫爪接口与提升

| 优先级 | 提升点 | 猫爪接口 | 接入后效果 | 兜底和边界 |
|---|---|---|---|---|
| **P0** | **当日涨跌停价有了权威来源** | `pricelimit`（第 3.1 节，`price_limits` 能力） | 不再出现「理论价仅作观察」，可以正常建计划；北交所、S 股、除权日都按交易所口径 | 猫爪失效时回退到现状（本地理论价，暂停建计划），不会变得更差 |
| **P0** | **证券交易状态（日级）** | `suspend`（停复牌）+ `st` + 上市日期 | 盘前就能确定当日 `trading` 或 `suspended`，大部分股票不再显示状态未知 | 只能覆盖**全天停牌**；**盘中临时停牌（临停）**仍需实时数据确认。拆成「日级状态」和「盘中状态」两个字段。**已决策：日级已确认、盘中未知时允许建计划**（防护条件见 11.6） |
| **P1** | **盘口兜底** | 猫头鹰 `tick` 五档（含买卖价、委托量为手、多代码批量） | depth5 有第三个来源；与封单服务共享兜底链和节流 | 整轮切换，不在同一轮混用来源；盘中刷新延迟**未测**，决定能否满足 10 秒时效门槛 |
| **P1** | **真实的 5 分钟板块和市场环境** | `minute-stat`（板块 5 分统计）、`themedaily_jx` 实时、`index_minute` | `sector_return_5m` 从「日涨跌幅差」近似升级为真实区间收益，趋势过滤更准 | 厂商的板块口径与本地板块目录不同，需要映射；保留现有口径作为兜底 |
| **P1** | **封板和风险事件** | `limit_event_v2` 或 WebSocket 异动订阅、`point-monitor` 交易监管、`anomaly-forecast` | 封板、炸板事件直接触发「封板不可成交」和风险退出提示；被重点监控或预计严重异动的持仓暂停新计划 | 只作为暂停或提示条件，不自动交易；WebSocket 需要专业版，**未测** |
| **P1** | **跨日回放的公司行动模型** | `stock_ex_rights`（需专业版）+ 分红送转 | 补上「首版没有公司行动模型」这个缺口，跨日 T+1 回放才有条件开放 | 2017 年前和缺失年份仍标为不可验证区间 |
| **P2** | **分时容量曲线** | 历史分钟（专业版近 3 年） | 容量从「日量除以 240」改为按分钟时段的历史中位数，早盘和午盘参与率更真实 | 本地已有分钟仓库，猫爪主要补深度 |
| **P2** | **分钟内成交顺序** | 分笔历史（专业版近 1 年） | 保守撮合时可以用分笔判断「触价」和「到期」的先后，减少因无法判断而整根跳过的分钟 | 分笔没有队列位置，仍然不能保证成交 |
| **P2** | **资金确认（研究用）** | `screening.main_net_amount`（当日累计主力净额，轮询差分得到区间值；5 分主力净额和 ddx 需旗舰版） | **已决策：作为证据展示**（信号详情展开区），同时写入 `signal_history` 供前向验证 | 厂商模型，**不进入硬过滤和条件判定** |
| **P3** | 盘前方向背景 | `daily_auc`、`auc_kp` | 当日竞价强弱作为当天做T方向的背景（偏先卖后买还是先买后卖） | 做T窗口从 09:30 开始，只作背景 |

**做T的核心提升**：前两项（权威涨跌停价、日级交易状态）能把「功能已接入，但实盘总是显示暂停」的现状变成**大部分持仓可以正常评估**，收益最大、改动最小，而且与第 7 节阶段 1 的 P0 能力完全复用。

### 11.3 持仓分析与计划：可接入的猫爪接口与提升

| 优先级 | 提升点 | 猫爪接口 | 接入后效果 | 边界 |
|---|---|---|---|---|
| **P0** | **风险状态排雷** | `st`、`suspend`、`point-monitor`、`anomaly-forecast` | 报告新增「风险状态」：ST、停牌、重点监控、预计严重异动。**已决策：命中时提示，确认后允许采纳**（见 11.6） | 只列事实，不生成交易动作 |
| **P1** | **业绩事件** | `forecast` 业绩预告、`express` 业绩快报、`disclosure-date` 披露计划 | 新增「近期事件」：财报披露日落在持有期内时提示，业绩预告类型（预增、预亏）作为证据 | 不做盈利预测，只列已发布事实和日期 |

| **P1** | **资金情景** | `fundflow_kp` 日主力净额、`longhubang_*` 个股上榜、`margin/detail` 个股两融、`northbound-holding` 北向持股 | 新增「资金」证据：近 N 日主力净额、是否上榜（含游资席位）、融资余额变化、北向持股变化。**已决策：作为证据展示** | 主力净额是厂商模型，标注口径，不打分、不进入情景价位 |
| **P2** | **公告与互动** | `announcement` 公告、`interactive-qa` 问董秘 | 作为现有巨潮公告排雷的第二来源和兜底；问董秘作为催化的人工参考 | 文本只做标题规则识别，不交给 AI 自由生成结论 |
| **P2** | **估值与股本** | `valuation`、`capital` 股本变动、`holder-number` 股东户数 | 估值分位、股本变动、筹码集中度作为波段研究的背景 | 只作背景，不进入情景价位 |
| **P2** | **市场情绪背景** | 本地情绪阶段 + `emoindic_daily` 旁证 | 报告显示当前情绪阶段，例如「退潮期的短线持仓风险更高」 | 本地阶段为主，猫爪只做旁证 |

**持仓分析的核心提升**：从「只有价格和板块的技术研究」扩展为「**价格 + 风险状态 + 事件 + 资金 + 板块**」五类证据。这正好对应文档中「本版未接入」的部分。AI 解读继续只引用程序证据，新增证据带来源和口径，模型不得自行生成数字或动作。

### 11.4 兜底与降级（遵循第 5 节的统一机制）

| 新增数据 | 猫爪失效时 | 页面表现 |
|---|---|---|
| 涨跌停价 | 本地规则计算 | 与现状相同：理论价只作观察，暂停建计划 |
| 交易状态 | 本地停牌和 ST 推断（无法确认时为 unknown） | 与现状相同：暂停判断 |

### 11.6 已确认的决策及其影响分析（2026-11-12）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 日级交易状态已确认、盘中状态未知时，做T **允许建计划** | 采纳 |
| 2 | 持仓分析命中风险状态时 **提示后允许采纳** | 采纳 |
| 3 | 资金类厂商指标 **作为证据展示** | 采纳 |

#### 决策 1：允许在「盘中状态未知」时建计划

**改动范围**：
- `position_t_market.py:133-136` 的硬门槛：从「`trade_status` 必须是 trading、suspended 或 delisted 之一」改为：
  - 日级状态为 trading，即可通过；
  - 盘中明确为 suspended 或 delisted，仍然阻断。
- 新增字段 `trade_status_basis: intraday | daily`。
- `docs/position-t-contract.md`、`position-t-monitor.md` 的「证券状态」一行同步改写。
- 计划和 `signal_history` 记录「盘中状态未确认」作为证据，复盘时可以统计这类计划的结果。

**剩余风险**：
- 盘中临时停牌。有涨跌幅限制的普通股票很少发生；上市初期无涨跌幅的窗口本来就已暂停。
- 风险主要集中在：交易所对异常波动的临停、重大事项的盘中停牌。

**防护依赖行情时间戳，这里发现一个必须先解决的问题**：
- 停牌股的成交时间会停止更新，现有「行情超过 10 秒未更新就暂停」的检查本可以兜住临停。
- 但实测代码显示，猫爪实时快照把 `timestamp` 写成**接收时间**：`plugins/meoz/provider.py` 的 `_quote_record` 中，当日数据使用 `now_ms`。
  - 原因是请求字段里没有逐股的成交时间。
  - 后果是停牌股也会显示为新鲜。
  - 这与做T契约「timestamp 必须是真实市场时间，不得用接收时间填补」**冲突**。
- 因此决策 1 必须配套以下其中一项：
  - **方案 A（首选）**：交易时段补测猫爪快照是否有逐股的最新成交时间字段，有的话就改用它。
  - **方案 B**：增加「疑似停牌」检测：连续竞价中，累计成交量连续 3 轮（或 1 分钟）不增加，且盘口不变 → 判为盘中疑似停牌，暂停新计划并提示。流动性极差的股票可能误报，但误报只会造成暂停，方向安全。
  - **方案 C**：盘口来源（tdxquant、TickFlow）带真实时间戳时，以盘口时间作为临停判据。
- **在方案 A 或 B 落地前，路由到猫爪实时行情的账户不应启用决策 1**。建议按行情来源能否提供真实市场时间戳来决定是否放行。

**自动模拟账户**：同样适用决策 1；风险退出逻辑不变（数据无法确认时保留敞口）。

#### 决策 2：风险状态提示后允许采纳

**交互（遵循 CONTRIBUTING 第 7 节信息精简）**：
- 报告行只显示一个风险标签，例如「风险 2」，展开后列出 ST、停牌、重点监控、严重异动预测等明细和来源。
- 点「采纳」时，若有风险命中，弹出确认框，逐条列出风险，用户勾选「已知悉」后才提交。

**契约**：
- `POST /api/holding-analysis/plans` 新增 `acknowledged_risks`（风险 ID 列表）。
- 服务端重新计算风险，要求**完全覆盖**当前命中项才允许采纳。如果在确认后风险有变化，返回版本冲突，避免确认的是旧风险。
- 计划证据保存「采纳时的风险项和确认时间」。

**风险来源不可用时**：
- 显示「风险状态未知（来源不可用）」，同样需要勾选确认后才能采纳。
- 不能当作「无风险」直接放行，这与「未知不是零」的原则一致。

**采纳后风险变化**（例如新增 ST、被列入监控）：
- 已采纳计划显示警示；
- **不自动作废**；
- 价格提醒按现有规则「版本变化默认暂停」处理，是否把风险变化纳入暂停条件，实施时再定。建议纳入，因为与现有的除权基准暂停逻辑一致。

**AI 解读**：可以引用风险证据，但只能使用程序模板文字。

**另一个未决定的点**：做T里「重点监控 / 严重异动预测」目前规划为暂停新计划（11.2 表）。决策 2 只针对持仓分析。做T建议：
- 人工账户也采用「提示后允许」；
- 自动模拟账户仍然暂停（没有人确认）。

如果不另行说明，就按这个建议执行。

#### 决策 3：资金指标作为证据展示

**展示位置**：
- 持仓分析：报告行展开区新增「资金」一栏，内容包括：近 5 日主力净额合计和方向、是否上榜龙虎榜（含游资席位名）、融资余额 5 日变化、北向持股变化。主列表不新增列。
- 做T：只在信号详情的展开区显示近 5 分钟和当日主力净额；候选行不新增信息。

**口径要求**：
- 每项都标注来源（猫爪）、单位（元）、数据截止时间、「厂商模型口径」；
- 盘后数据不得在盘中被当作当日数据；
- 回放只使用当时已可用的数据（`available_at`）。

**不做的事**：
- 不打分；
- 不进入硬过滤、情景价位和条件判定；
- AI 解读不得根据资金数据推断「主力意图」。

**来源不可用时**：显示「资金数据不可用」，不显示 0。

**前向验证**：资金证据随信号写入 `signal_history`、随报告保存。积累足够样本后，再评估是否值得升级为过滤条件；这需要单独决策。

#### 新增的交易时段补测项

- 猫爪实时快照有没有逐股最新成交时间字段（决定决策 1 的防护方案）；
- 盘中临停股在猫爪快照和五档中的表现（价格、成交量、时间戳是否冻结）；
- `main-fund-flow-5m` 盘中更新延迟（决定做T展示时的数据截止时间）。
