# 市场情绪：开盘啦数据覆盖与缺口

本文核对用户提供的《开盘啦 API 接口文档.md》与仓库现有开盘啦目录、请求客户端和解析测试，说明市场情绪页面各项数据的来源、口径和缺口。文档中的示例响应不代表线上接口已经验证可用；请求成功、字段完整、日期一致后才可以显示业务数值。

情绪指标、直播解读及关联个股使用开盘啦接口数据。按用户追加授权，大盘直播中的**上证指数分时图**复用系统配置的分钟数据源，图表独立标明来源；其他开盘啦缺项不使用别的来源补齐。空数据、请求失败、认证受限和未提供接口分别显示，不能以 `0` 代替缺失值。

页面个股交互复用连板梯队的 `StockPreviewDialog`（L2 扩展页面接线）：回撤名单、权重龙头、涨停/首板破板表格的代码和名称，以及直播关联个股卡片可打开同一详情弹窗。日 K、分时及详情行情沿用系统数据源和弹窗默认日期范围；不把历史情绪日期冒充详情行情日期。切股范围为当前完整榜单（跨表格分页）或单条直播关联个股，按首次出现去重；关闭、切换页面日期或主标签后清空预览。仅已声明的个股字段转换成完整沪深北代码，指数、板块及异常代码不提供个股入口。未增加 API、查询键或持久化，详情复用现有共享查询与缓存。

## 1. 已有接入边界

- 请求目录：[`backend/app/services/kaipanla_catalog.py`](../backend/app/services/kaipanla_catalog.py)，声明接口、域名、参数、字段和解析规则。
- 请求客户端：[`backend/app/services/kaipanla.py`](../backend/app/services/kaipanla.py)，复用匿名请求、分页完整性校验、日期校验和缓存；不接受 `Token`、`UserID`、Cookie 或 Authorization。
- HTTP 入口：[`backend/app/api/kaipanla.py`](../backend/app/api/kaipanla.py)，挂载于 `/api/market-recap`。市场情绪聚合入口为 `GET /api/market-recap/kaipanla/market-emotion`，另有 `/kaipanla/catalog`、`/kaipanla/query/{dataset_id}`、`/kaipanla/context` 和 `/kaipanla/refresh`。
- 独立聚合服务：[`backend/app/services/market_emotion.py`](../backend/app/services/market_emotion.py)，复用匿名客户端，不读取本地价格。无日期参数时从供应商情绪历史确定最近有记录的日期；显式日期只查询该日，不静默回退。响应包含目标日、上一记录日、各项数据、最多 60 个情绪历史点和缺口清单。
- 历史读取：客户端的 `include_history=True` 只允许情绪接口。`normalize_emotion_history` 最多接受 1000 行，要求每行具有唯一、无冲突的日期，排除查询时点之后的记录，同日相同记录去重、冲突记录拒绝。历史缓存和默认单日快照缓存隔离，历史行的 `trade_date`/`date` 保留供应商真实日期。
- 现有摘要：[`backend/app/services/kaipanla_context.py`](../backend/app/services/kaipanla_context.py)，只读取目标日八个扩展分区的有界摘要。它不包含全部目录数据，也不公开直播的 `ShareData_json`，不能直接用作完整市场情绪数据集。
- 解析依据：[`backend/tests/test_kaipanla_catalog.py`](../backend/tests/test_kaipanla_catalog.py)。测试证明固定样本的解析规则，不证明线上匿名接口的可用性。

原文档包含 43 项功能，现有匿名目录排除三个明确要求登录凭据的功能和一个认证说明不明确的竞价列表，共声明 39 项。不能为缺项猜测未记录的 `a`、`c`、参数值或域名。

## 4. 日期、来源时间与单位

1. **数据日期、来源时间、获取时间分别保留。** 供应商日期用于核验目标日，消息或快照时间用于说明数据观察时点，`fetched_at` 仅表示客户端取数时间。请求参数中的日期不能冒充响应确认日期。
2. **只使用文档声明的今日路由。** 梯队统计、涨停列表、破板列表及直播有明确今日域名或 controller。情绪、量能、涨跌停总数、涨停表现、大幅回撤、权重表现及竞价总览/数量在文档中只声明历史域名，应使用原有 `apphis` 路由，不猜测 `apphwhq` 下的其他 controller。
3. **跨日图表保持业务日期。** 供应商返回多日情绪行时，每一行对应自己的 `Day`。缺少完整数据时显示部分覆盖及缺失日期，不补零、不复制最近值。
4. **金额只按声明单位转换。** 市场量能的 `last` 等字段单位是万；亿元显示除以 `10000`。其他接口金额沿目录明确注明的单位，不按数值大小猜单位。
5. **百分数显式使用。** 供应商涨跌幅、晋级率、破板率和回撤幅度按百分数展示；不得混入标准行情源的小数比例口径。
6. **不把不同榜单直接混算。** 涨停总数、直播统计、首板/连板榜单、实际涨停和全部涨停可能存在范围差异，先注明来源与范围，不用榜单去重数量替代供应商总数。

直播示例尤其需要单独核验消息日期：文档示例顶层 `date` 为 `2026-04-17`，但消息 `Time=1776236400` 对应北京时间 `2026-04-15 15:00:00`。顶层日期可以是直播包日期，不能证明其中每条消息均为该日统计；这样的消息不可当作 4 月 17 日的涨跌分布。目录解析器检查显式日期字段，市场情绪聚合层进一步以消息整数时间戳校验统计日期。

## 5. 缺口清单

- 未提供接口或字段：指数分时图及成交量分钟序列、量能分钟曲线、活跃股走势、连板强度及其分钟/历史序列、连板股专属回撤、截图同名风向标、独立封板率、四板与高度板各自的晋级率、全板位今日炸板名单、跌停股票名单；回撤名单所属板块及截图中的融资、游资、基金、风险标签也没有可用于此页的完整字段契约。
- 有文档字段但需要条件满足：直播涨跌分布需目标日完整嵌套统计；历史情绪需保留各行日期；昨日对照需确定前一有效交易日；仅历史域名的接口当日是否及时可用需按实际请求确认。
- 明确需要登录：板块竞价、板块内股票竞价、最强风口。
- 认证要求待确认：竞价股票列表。

上述开盘啦缺口保留在页面并解释原因。其中指数分时接口仍属于开盘啦缺口，但图表已按用户授权使用系统分钟源。其余缺口待新增真实接口文档或完成认证要求核验后再扩展目录；不使用隐藏 API、截图数值或模拟曲线填充。

### 大盘直播分时的来源与缓存

- 接入在 `frontend/src/custom/kaipanla/LiveIndexChart.tsx`，复用共享 `EChartsIntraday`；直播及股票数组继续由开盘啦聚合响应提供，不逐只请求其他行情源。
- 分钟查询键复用 `QK.indexMinute`，新增可选 provider 维度，旧调用不变。后端既有缓存已包含代码、日期及分钟源；切换源后新页面不沿用旧源数据。
- 昨收通过既有指数日K接口读取目标日前 60 个自然日范围，在结果内取最后一个真实交易日，而非将目标日减一天当作交易日。窗口内无有效昨收时不显示涨跌幅，也不用首个分钟点代替。
- 仅当直播日期为北京时间当日且处于交易时段窗口时每 60 秒刷新分钟图，历史日期不轮询。接口的 `source=live` 代表在线读取，不代表历史数据属于今日。刷新失败保留同源同日有效图并提示；切换日期或数据源不继承旧图。
- 共享图表新增可选 `annotations`、`onAnnotationClick` 及 `connectNulls`，未传入时保持旧行为。本页关闭缺口连线；标点使用消息北京时间 `HH:mm` 对齐，缺口、盘前、午休和盘后消息不插值；关联个股的来源涨幅仍不能声称为消息发布时的即时涨幅。
- 板块及大盘强弱标注从同日直播 `Comment` 提取简短原文片段，每条消息最多两个：明确走强、拉升、回流、修复等显示红色，走弱、回落等显示绿色，其他消息显示灰点。只接受明确板块、指数或短线情绪主体，个股叙述、预测、条件、否定、历史回顾及方向冲突不作强弱标注。这是直播观点的文字整理，不是新增实时板块强度指标，也不按指数线涨跌替板块作判断。
- `IntradayAnnotation` 的可选 `caption` 控制文字框，`direction` 控制红、绿、灰颜色；原 `label` 保留消息摘要。密集标签自动避让，所有匹配真实分钟的强弱标注可在图下展开、用键盘选择并定位原消息；隐藏文字标注仍保留可点击标点。不增加网络请求、后端字段、持久化或查询键。
