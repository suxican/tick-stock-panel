# 持仓分析与操作计划

入口：`/lots` → **持仓分析与计划**。这是独立的持仓研究功能，现有做 T 两腿计划、成交账本及批次提醒继续沿用原接口。

## 使用

1. 选择“批次参考”或明确的核对持仓账户。两种来源分别分析，不合并计仓。
2. 编辑个股研究设置：首次建仓交易日、短线／波段周期、新建仓窗口、预计最长持有、买入理由、研究失效条件、可选的最大亏损阈值、深度浮亏阈值和主要关联板块。点击“保存研究设置”后再生成分析。
3. 点击“生成分析”。新建仓、成本状态、趋势、相对板块强弱分别显示，可同时出现“刚建仓”和“浮盈／深度浮亏”。
4. 展开查看行情时间、价格口径、板块覆盖、研究设置及基准／走强／走弱情景。资料完整且无冲突时可采纳，保存当时的证据与规则结果。
5. 已采纳计划可查看原始依据、作废或绑定走强／走弱的价格提醒。已有同股已采纳计划须先明确作废，不能靠刷新报告重复创建。
6. 可选点击“AI 解读依据”，调用用户已配置的模型整理程序证据引用和关注类别。说明文字由程序模板生成，不采用模型自由文字，避免模型自编中文或数字价位及交易动作。不会自动调用模型；模型异常不影响规则结果。解释按纯文本显示，不改价格、数量或计划条件。

研究阈值与期限为可调整的研发初值。最大亏损阈值会收紧走弱情景的参考价，但不能保证退出成交。所有计划均不下单、不生成成交、不预留库存或资金；本页不计算可执行股数。

## 数据与降级

- 批次只含参考数量、参考成本和买入日期。同股加权参考成本沿用批次语义；无效或损坏批次不会被悄悄忽略后计成完整持仓。批次日期未知时不能用文件创建时间填补。
- 核对持仓读取既有账本的数量、成本口径、可卖、预留、快照版本及未完成做 T 计划。核对时间不是建仓时间；做 T 成交不代表登记成本已自动更新。只有批次来源时，同股其他账户的未完成做 T 计划仍作为冲突警示，不合并其数量。
- 盈亏为原始价格相对登记参考成本的价差，不等于包含费用、已实现收益和公司行动的完整会计收益。当前登记成本需人工核验。
- 日级研究仅采用完整交易日；计算交易日年龄和期限使用有来源的项目交易日历。日历覆盖不足以确定到期日时，禁止采纳和数值触发。应按项目交易日历维护流程更新日历。
- 技术形态使用现有仓库复权序列，复用关键价位计算；只有原始价映射能够核验时才输出原始价格条件。报价与日线的除权基准不一致时暂停采纳和提醒。
- 板块通过完整成员目录反查，保留来源身份，同名不同来源不混合。按实际覆盖率判断有效性；榜外板块不视为弱势。成员是当前归属，不能据此声称严格历史归属。
- 缺少实时数据时仍可做完整日线研究；缺成本、建仓日、失效条件、有效板块证据、完整日线或存在未完成做 T 敞口时，会显示缺口并限制采纳。未知值不是零分。
- 本版未接入新增消息、资金流或基本面供应商；不据此生成未经核验的催化、资金判断、盈利概率或完整账户仓位建议。

## 计划与价格提醒

报告、研究资料、计划分别版本化。生成前后检查输入版本；采纳时再核验持仓、整批研究配置、分析日期与期限。旧报告可查看，不能按当前结果采纳。

提醒只检测所选的**原始价格阈值**，不代表板块、量价及人工条件已同时满足。仅站内提醒，默认不发送外部 Webhook。价格触及不表示委托或成交。

提醒仅当日有效。跨日、研究配置或持仓版本变化、计划作废、行情暂停／过期、除权价格基准变化时默认暂停。重新研究并显式绑定后才恢复；旧触发不会自动复活。

绑定采用持久化 `pending → 规则启用并同步 → active`。任何未完成绑定在后台刷新和重启后都保持暂停。监控中心不能改写或删除托管规则，应回到本页操作。守卫在独立线程读取必要事实；行情回调只检查有期限的内存准入，不做研究计算、AI 或磁盘扫描。

## 实现与兼容

主体采用 L2：既有前端扩展页、后端路由注册、统一 API 客户端与查询键。局部 L3 仅用于守卫生命周期、监控引擎的内存准入和托管规则保护；没有继承或复制做 T、仓库及监控大服务。

研究文件：`data/user_data/holding_analysis/state.json`，schema 版本 1，使用既有原子写底座、同路径共享锁及版本冲突检查。损坏或高版本资料拒绝覆盖。最多保留 100 份报告；已采纳计划嵌入原始行，报告归档不会删除其证据。文件含个人研究资料，应按用户数据管理。

没有迁移、覆盖批次 JSON、做 T SQLite 或行情文件。研究不另建行情缓存；持仓批量去重、板块共享快照，前端按来源和账户隔离查询，写入后精确失效。研究文件无额外内存缓存，后台守卫只保留短时准入租约。

内部 API 前缀为 `/api/holding-analysis`：

- `GET /overview`：来源、账户、当前输入、研究配置、最近报告、已采纳计划。
- `POST /analyze`：按服务端事实生成并保存报告。
- `PUT /profiles/{key}`：带预期版本修改研究设置。
- `POST /plans`：采纳服务端报告的指定行。
- `PATCH /plans/{id}`：带预期版本作废计划。
- `POST /plans/{id}/alerts`：绑定所选情景的价格提醒。
- `POST /reports/{id}/interpret`：按需解释已保存程序证据；AI 结果不落盘。

均沿用应用登录认证；没有扩展外部 Token 权限。升级时重点复核 `main.py`、监控引擎准入、托管规则保护、前端公共 API 类型和查询键。回滚时保留研究目录；缺少守卫的版本不应启用带 `holding_plan_id` 的价格规则。
