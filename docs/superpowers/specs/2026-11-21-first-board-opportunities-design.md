# 首板「机会记录」读侧聚合（设计，待确认）

> 日期 2026-11-21。状态：方案已选定（只做读侧聚合），本文待你确认后再写实施计划。不改事件写入、通知、回放、排名和模拟买入。

## 1. 目的

设计稿里的盘后复盘页要“一股一条机会记录”：首次提示、首次触板、开板、回封、最后状态，并能筛出“封板未提示”。现在只有原始事件列表（`GET /api/first-board/events`），同一只股票的多个形态、反复切换会产生几十条记录，前端无法直接做成复盘行。目标：后端提供按股票聚合的只读接口，原始事件原样保留。

## 2. 接口

`GET /api/first-board/opportunities?day=YYYY-MM-DD&revision=N`

- `day` 必填；`revision` 缺省时与首次提示排名同一选法（有买入候选的最新版本，否则当天最新版本）。所选日期没有这个版本时返回 400，与排名接口一致。
- 只读已保存的当日事件档案，不读行情、不读日线、不读账本。事件为空时返回空列表，不报错。
- 返回 `rows`（每只股票一条）和 `summary`。

每条 `rows` 含：

| 字段 | 含义 |
| --- | --- |
| `symbol` / `name` | 股票 |
| `patterns` | 当天出现过的全部形态（`pattern`、`pattern_label`），按首次出现先后 |
| `first_alert` | 该股当天最早的 `buy_candidate`：`at`（毫秒时间戳转北京时间 ISO）、`price`、`pattern`、`event_id`；没有则为 `null` |
| `first_touch` | 最早的 `sealed` 事件：`at`、`price`；没有则为 `null`。这是“涨停价观察”，不代表封单或可成交 |
| `broken` | 首次 `broken` 事件的 `at`；没有则为 `null`。只统计 `first_touch` 之后的 |
| `resealed` | 开板之后再次出现 `sealed` 的最早 `at`；没有则为 `null` |
| `last_state` | 最后一条事件的 `event_type` 与 `at`。这是盘中最后一次观察，不是收盘结果 |
| `first_record` | 该股当天最早的任意事件：`at`、`event_type`、`blocked_reasons`。用来回答“封板未提示”的股票最早什么时候被记录、当时被什么挡住 |
| `alerted` | `first_alert` 非空 |
| `sealed_unalerted` | 有 `first_touch` 且没有 `first_alert` |
| `event_count` | 该股当天原始事件条数（`exit` 形态不计入，见下） |

`summary`：`stock_count`、`alerted_count`、`touched_count`、`sealed_unalerted_count`，另附 `revision`、`day`、`available_revisions`。分母都是“当天有记录的股票数”，不混用提示股与漏选股。

## 3. 口径与取舍

- **一股一行**：同股多形态合并；时间节点取所有形态里最早/最近的，并保留 `first_alert.pattern` 说明是哪个形态先提示。
- **排除退出提示**：`pattern == "exit"` 的事件（次日退出提示）不是板前机会，不参与聚合。
- **事件时间**：用事件里的 `ts`（毫秒），转北京时间输出；缺失或类型不对的事件跳过并计入 `skipped_count`，不猜。
- **去抖不在这里做**：同一状态反复出现只会让 `event_count` 变大，聚合取最早/最近，结果不受重复影响。
- **“封板未提示”的判定只看本版本事件**：没有 `buy_candidate` 即视为未提示，不区分是被行业挡住还是首条记录已触板；原因由 `first_record` 的 `event_type` 和 `blocked_reasons` 给出，前端自己说明。

## 4. 目标、非目标、反目标

**目标**：一次请求拿到复盘页需要的全部事件侧数据；结果可由原始事件完全复算。

**非目标**
- 不提供收盘结果（收盘封板/未封）和模拟成交核验：它们要读日线和模拟账本，口径另有交易链验证，下一步单独做。接口里不放占位字段，前端对应列显示“待核验”。
- 不改事件写入、通知冷却、`place_order`、交易链回放、首次提示排名。
- 不做前端页面；本次只交接口和测试。

**反目标**
- 聚合结果与排名接口的“首次提示”对不上（同一天同一版本，`first_alert.at` 应与排名里的 `signal_at` 一致）。
- 把“最后一次盘中观察”显示成“收盘封板”。
- 读接口写入或改动事件档案。

## 5. 方案对比

| 方案 | 取舍 |
| --- | --- |
| **A. 新增只读聚合接口（选定）** | 不影响交易链；前端一次请求；逻辑集中、可单测 |
| B. 前端在浏览器里聚合 `events`（上限 5000 条） | 不改后端；每个页面重复实现，超过上限会静默截断，口径易与排名漂移 |
| C. 写入侧一股一条 | 已否决：破坏 `event_id` 到模拟订单的归因链 |

## 6. 我定的选择（请核对）

1. **接口放在首板现有路由下**，新增 `app/services/first_board_opportunities.py` 放纯函数，服务层和路由只做读取和参数校验。
2. **版本选择复用排名的规则**，避免两个接口默认版本不一致。
3. **不加缓存**：当天事件文件有每日上限，聚合是一次线性扫描；若实测慢再参照排名的文件签名缓存。
4. **时间一律输出北京时间 ISO**，与排名接口一致。
5. **`first_touch` 取事件里的 `sealed`，不引入交易所触板流**：交易所触板时间属于另一条数据链，混入会让接口依赖行情服务。

## 7. 验证

- 纯函数测试：同股多形态合并；提示→触板→开板→回封顺序；只触板未提示；退出事件被排除；缺失 `ts` 被跳过；重复事件不改变结果；空输入。
- 接口测试：参数校验（缺日期、非法版本）、默认版本选择、与排名接口的首次提示时间一致。
- 跑后端首板相关测试和新增测试；不做浏览器验证（没有前端改动）。
