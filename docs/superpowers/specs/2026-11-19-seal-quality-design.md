# 情绪周期新维度：封板质量（设计与计划）

> 日期：2026-11-19
> 依据：`docs/猫爪数据对接/猫爪数据对接规划.md` 4.1 节（阶段判定升级为「宽度 + 封板质量 + 竞价情绪」，规则改动先离线验证）。
> 范围：这一轮只做封板质量，只展示，不改阶段规则；另交付一份离线对比报告。竞价情绪留到下一轮。

## 1. 意图
现有情绪周期阶段完全基于收盘连板（最高板、各档宽度、晋级率、收盘封板率），看不到盘中的炸板、开板和封板早晚。猫爪涨停池已按日归档（2018-09-12 起，1983 天），可以回算这些维度。本轮先把它们展示在【市场环境】页，并用离线报告说明它们与现有阶段的关系，为以后是否修改阶段规则提供依据。

**非目标**
- 不改 `market_phase` 阈值与判定规则，不改 `regime_history` 表。
- 不做竞价情绪。
- 不新增上游调用（只读本地归档）。

## 2. 实测依据（本地数据，2026-11-19）
- **全量计算成本**：从日线 enriched 读取 `symbol, date, consecutive_limit_ups`，加上从涨停池读取若干列，全部历史约 1–2.3 秒（含按日 ST 判定）。因此不另建汇总表，按请求计算并在进程内缓存。缓存签名为涨停池目录，以及参与计算的日线日期目录：盘中当日日线每约 15 秒重写一次，当日涨停池 15:45 才落盘，在此之前这些写入不应让缓存失效（终审发现）。只对同时有涨停池和日线分区的交易日出行，避免日线缺失时给出 100% 炸板的误导值。
- **炸板占比**：各年稳定在 25–29%。
- **开板次数 `open_times`**：
  - 2018-09 至 2019-12 为 0 或 null，属于字段缺失；
  - 2020-01-02 起才有真实值，约一半涨停股盘中开过板。
  - 2020–2023 年另有 6927 行为 null，实测**全部是当时的 ST 股**，默认剔除 ST 时不参与计算。不剔除 ST 时按「首封时间 ≠ 末封时间」判断是否开过板：在非 null 行中，两者一致率为 99.8%（终审发现）。
- **`first_time`**：2018 年起都有，早盘封板占比各年合理。
- **`limit_detail`**：只有 2026 年有，不用。
- **日线收盘涨停但不在涨停池的行**：共 11844 行。
  - 2021 年后有 9720 行，其中 8082 行是当日 ST，因为涨停池本身不含 ST，我们反正要剔除；
  - 其余少量个股缺失，这些股计入「收盘封板」，但没有首封时间、开板次数、封单额。
- **猫爪 `ub` 但收盘涨停**：2172 行，即尾盘回封。以日线收盘为准，计为封住。
- **封单额口径变化（实现时发现）**：`fd_amount` 在 2020-05 至 2023-11 的量级约为其它年份的 1/600。封单额/成交额的中位数约 0.02%，而正常年份约 10% 以上，说明上游口径不同，并非缺失。不臆测换算：按日判断，封单额/成交额的日中位数低于 0.5% 时，该日 `fd_median` 为 null。
- **2018–2019 年炸板率虚高（实现时发现）**：初算约 0.40，2020 年后约 0.25。原因有二：
  - 2019 年 1794 行「涨停池为涨停、日线不认涨停」中，1667 行是当时的 ST（2021 年前没有按日 ST 名单，当前名单漏掉了已摘帽的股）；
  - 其余多为新股上市初期（名称以 N 或 C 开头，涨跌幅规则不同）。
  
  按涨停池中**当时的股票名**剔除这两类之后，2018–2019 年炸板率约 0.27，与后续年份一致。

## 3. 口径（只看涨停一侧，剔除 ST）
- **ST 剔除**：沿用情绪统计的开关 `preferences.get_sentiment_exclude_st()`，实现复用 `market_reference.exclude_risk_warning(df, load_risk_warning_symbols(data_dir))`，按日名单优先。另外，涨停池中当时的股票名含「ST」的股，同日的涨停池行和日线行一并剔除。
- **新股上市初期**：涨停池中当时名称以 N 或 C 开头的股，同日的涨停池行和日线行一律剔除，不受开关影响。
- **收盘封住** `sealed`：日线 `consecutive_limit_ups >= 1`，与现有情绪周期的涨停数同一口径。
- **盘中触板** `touched`：涨停池 `type ∈ {u, ub}` ∪ `sealed`。
- **每日指标**：

| 字段 | 定义 | 起始 |
|---|---|---|
| `touched` / `sealed` | 家数 | 2018-09-12 |
| `break_rate` | `1 - sealed / touched`；`touched = 0` 时为 null | 2018-09-12 |
| `reopen_rate` | 收盘封住且有涨停池记录的股中 `open_times > 0` 的占比 | **2020-01-02**，此前为 null |
| `early_share` | 收盘封住且有首封时间的股中 `first_time <= 10:00:00` 的占比 | 2018-09-12 |
| `late_share` | 同上，`first_time >= 14:30:00` 的占比 | 2018-09-12 |
| `oneword_share` | 同上，`first_time <= 09:30:00` 的占比（开盘即封） | 2018-09-12 |
| `fd_median` | 收盘封住股封单额中位数（元） | 2018-09-12 |
| `pool_coverage` | 收盘封住股中有涨停池记录的占比 | 2018-09-12 |

- 时间比较用 `HH:MM:SS` 字符串字典序。北京时间，零填充格式已核实。
- 某日涨停池分区不存在：该日不出行，不按 0 处理。
- **近一年分位**：对最新一天，用此前 250 个交易日（含当天）计算各指标的分位，0–100。样本少于 60 天时为 null。

## 4. 实现

### 后端
- 新模块 `backend/app/services/seal_quality.py`：
  - `compute_seal_quality(data_dir, *, exclude_st: bool | None = None) -> pl.DataFrame`：全量计算，返回每日一行，按日期升序；
  - `load_seal_quality(data_dir) -> pl.DataFrame`：带进程内缓存（签名同上）；
  - `seal_quality_payload(data_dir, start, end) -> dict`：返回 `{"rows": [...], "latest": {...指标, "pct": {指标: 分位}}, "first_date", "reopen_from": "2020-01-02"}`。
- 新接口 `GET /api/regime/seal-quality?start=&end=`，放在 `api/regime.py`。

### 前端（`frontend/src/pages/Regime.tsx`，情绪周期视图）
- 新卡片「封板质量」，放在「情绪周期时间轴」之后：
  - 最新一天 4 个指标：炸板率、早盘封板占比、开板率、封单额中位数，每个附近一年分位；
  - 折线图：炸板率、早盘封板占比、开板率，日期范围与页面区间一致；
  - 说明行（灰字）：口径与「开板率 2020-01-02 起」，「涨停池覆盖率」悬停显示。
- 时间轴「当日快照」加上当天的炸板率与早盘封板占比（有数据时显示）。
- `api.ts` 新增 `regimeSealQuality(start, end)` 与类型。

### 离线对比报告
- 一次性脚本（不提交）计算 2020-01-02 之后（开板率可用区间）每个阶段的各指标分布（中位数、p25、p75），各指标与现有 `seal_rate` 的相关性，以及各指标对次日全市场等权涨幅的分组差异（按指标三分位）。
- 结论写入 `docs/情绪周期/封板质量离线对比.md`，只列事实，不改规则。

## 5. 测试
- `test_seal_quality.py`，用 tmp 目录造 enriched 与 limit_events 分区：
  - 尾盘回封（`ub` 但收盘涨停）计为封住；
  - 只在日线涨停、不在涨停池的股计入 `sealed`，但不进时间、开板统计，`pool_coverage` 正确；
  - 2020 年以前 `reopen_rate` 为 null；
  - ST 剔除（按日名单）；
  - 涨停池缺分区的日子不出行；
  - `touched = 0` 时 `break_rate` 为 null；
  - 分位样本不足时为 null；
  - 缓存在新增分区后失效。
- 接口测试：区间过滤、空数据。
- 前端组件测试：指标渲染；开板率 null 显示「—」；分位显示。

## 6. 我做的决定
1. 不存汇总表，按请求计算并缓存（全量不到 1 秒）。
2. 收盘封住以日线为准（与现有涨停数同口径），猫爪 `type` 只用来扩充「触板」集合。
3. 早盘界线 10:00、尾盘界线 14:30、一字界线 09:30。
4. 分位窗口 250 个交易日，最少 60 天。
