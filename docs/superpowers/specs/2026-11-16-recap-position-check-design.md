# 复盘「今日执行」仓位核对 设计

状态：待审阅 · 2026-11-16

## 1. 意图

用户每天收盘后在环境页按 9 格预设得到第二天的仓位上限，系统已把结论存档（`user_data/environment_conclusion/`）。本设计在复盘页"今日执行"里核对：复盘日收盘时的实际持仓占比，有没有超过前一交易日定下的上限，并累计记录守住与超出的天数。目标是回答"我有没有按自己的规则做"。

## 2. 目标、非目标与反目标

**目标**

- 用户在批次页填写账户规模，可随时修改；每次修改按生效日期留档。
- 复盘快照的"今日执行"新增仓位核对：持仓市值、占比、适用上限、是否超限。
- 累计统计：已核对天数、超限天数，按格子分组。

**非目标**

- 按"守住 / 超出"统计盈亏。这需要逐日账户净值，而批次模块明确不做会计（上一期反目标）；以后可改用已结清交易按买入日格子分组来回答，本期不做。
- 自动读取券商总资产或持仓。
- 修改批次的结清、删除行为。

**反目标**

- 账户规模或持仓金额进入发给模型的提示词或外部推送。
- 缺账户规模、缺收盘价或缺存档时仍给出"未超限"结论。
- 买入日期缺失的批次被当作一直持有而不做标注。

## 3. 约束

- 遵循 `CONTRIBUTING.md`；API 薄层；前端请求走 `api.ts`、查询键走 `queryKeys.ts`；新增运行时数据须更新 `docs/data-directory.md`。
- 价格用复盘日原始收盘价（复用 `market_recap_holdings._raw_closes`），盘中快照不判定，与现有止损核对一致。
- 占比、上限对外为百分数（与复盘快照"百分比字段均为百分数"的约定一致），边界处加单位测试。
- 日期按北京时间与交易日。

## 4. 设计

### 4.1 账户规模

- 偏好键 `account_size_history`：`[{"effective_date": "YYYY-MM-DD", "amount": 500000}]`，金额为人民币元、正数，按生效日期排序，同一生效日期后写覆盖前写。
- `account_size_on(day) -> float | None`：取生效日期不晚于 `day` 的最后一条。
- 接口：`GET/PUT /api/settings/preferences/account-size`，PUT 体 `{"effective_date", "amount"}` 追加一条；`DELETE` 不提供（历史核对依赖它）。
- 批次页顶部显示"账户规模 50 万（2026-11-16 起）· 修改"，修改时默认生效日期为今天。

### 4.2 复盘日持仓

复盘日 D 收盘时的持仓：

- 未结清批次：`buy_date ≤ D`。`buy_date` 为空时用 `created_at` 的北京日期代替，并计入 `inferred_lots`。
- 已结清记录：`buy_date ≤ D < sell_date`（D 当天卖出的不算）；`buy_date` 为空时不计入，并计入 `unknown_lots`。
- 市值 = Σ 数量 × D 原始收盘价。任一持仓缺收盘价时整体不判定。

### 4.3 适用上限

D 的交易受前一交易日 P 收盘后的决定约束：读取 `environment_conclusion/<P>.json`，取 `recorded_at` 早于 D 当天 09:30（北京时间）的最后一版，使用其 `effective_cap_pct`、`cell`。P 取 `regime_history` 中 D 之前的最后一个日期。没有符合条件的版本时上限为空，原因"前一交易日无结论存档"；该版生效上限为空（未设置预设）时原因"前一交易日该格未设置预设"。

### 4.4 核对结果

`build_execution` 返回值新增 `position_check`：

```json
{
  "date": "2026-11-17",
  "position_value": 312000.0,
  "account_size": 500000.0,
  "ratio_pct": 62.4,
  "cap_pct": 80,
  "cap_date": "2026-11-16",
  "cell": "strong_expand",
  "exceeded": false,
  "inferred_lots": 2,
  "unknown_lots": 0,
  "reason": null
}
```

- `exceeded` 只在占比与上限都可算时为布尔值，否则为 null，`reason` 写明原因（"未填写账户规模""盘中不判定""缺收盘价""前一交易日无结论存档"等）。
- 空仓时占比为 0，照常核对。

### 4.5 累计统计

`stats` 新增 `position_days`：截至 D，最近最多 120 个有结论存档的交易日逐日重算 4.2–4.4，汇总 `checked`（可判定天数）、`exceeded`、`by_cell`（每格的天数与超限天数）。存档从 2026-11-16 起积累，初期天数很少，页面如实显示。

### 4.6 展示与隐私

- 复盘页"今日执行"新增一行："仓位 62%（上限 80%，强·放量）· 未超限"；超限时用警示色；不可判定时显示原因。买入日为推断的批次数大于 0 时附注"x 个批次买入日按登记日推断"。
- 下方一行累计："已核对 n 天 · 超限 m 天"，展开后按格子列出。
- 提示词只给"仓位占比、上限、是否超限、累计超限天数"，不给账户规模、市值。外部推送沿用现有剥离规则。
- 批次页对买入日期为空的批次显示"未填买入日"提示。

## 5. 验证

- 账户规模：追加、同日覆盖、按日期取值、非法金额拒绝、接口往返。
- 持仓：buy_date 边界、D 当天卖出不计、buy_date 缺失时用登记日并计数、已结清无 buy_date 不计入并计数。
- 上限：取 09:30 前最后一版、09:30 后的版本不用、无存档、该格未设置。
- 核对：超限、未超限、恰好相等（不算超限）、空仓、缺账户规模、盘中、缺收盘价。
- 统计：多日汇总与按格分组；提示词不含金额（断言账户规模与市值数字不出现在文本中）。
- 前端：RecapExecution 与批次页组件测试，`pnpm build`；临时数据目录实测。

## 6. 我自行决定、未经用户确认的事项

- 账户规模放在批次页编辑，而非环境页或设置页。
- 适用上限取前一交易日存档中 09:30 前的最后一版（盘前改预设算数，开盘后改的不算当天）。
- 买入日期缺失的未结清批次按登记日推断并标注；已结清的不计入。
- 恰好等于上限不算超限。
- 统计窗口最多 120 个存档交易日；本期不做按守住 / 超出的盈亏统计。
