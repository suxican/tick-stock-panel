# 首板页按时段调整默认布局（设计，已确认）

> 日期 2026-11-21。状态：用户已确认方案，纯前端、不改后端和任何买入逻辑。

## 1. 目的

一天里看首板页要的东西不同，现在页面不管几点都是同一个样子：竞价前要看昨日首板的竞价表现，却要先点“展开分布”、再点“查看明细”，排序还默认是“涨幅”；收盘后默认仍是“今日盯盘”。目标：按进入页面时的时段给出合适的默认布局，且不覆盖用户的明确选择。

## 2. 时段（北京时间，进入页面时判断一次）

| 时段 | 条件 | 默认行为 |
|---|---|---|
| 竞价前 | 周一至周五 09:15 ≤ 时间 < 09:30 | 展开“昨日首板反馈”和个股明细；个股排序默认“竞价涨幅”（有竞价数据时） |
| 收盘后 | 周一至周五 时间 ≥ 15:00 | 地址里没有 `tab` 参数时，默认打开“信号记录” |
| 其他 | 周末、09:15 前、09:30–15:00 | 与现在完全一致 |

- 时段只在页面挂载时判断一次，之后不因时间流逝自己改变。
- 不判断节假日（节假日 09:15–09:30 打开也会展开，无害）。

## 3. 不覆盖用户的选择

- 地址里已有 `tab` 参数（点过标签、从提醒弹窗进来）一律按地址走。
- 竞价前窗口内，“展开分布／收起分布”只对本次访问有效，**不读取也不改写**用户保存的偏好（`first-board-feedback-expanded`）；窗口之外行为不变。
- 用户手动选的个股排序始终优先于默认排序。
- 竞价数据缺失时，默认排序自然回退到“涨幅”（沿用现有回退逻辑）。

## 4. 目标、非目标、反目标

**目标**：竞价前一进页面就是竞价明细并按竞价涨幅排序；收盘后一进页面就是当日信号记录。

**非目标**
- 不加设置项，不在页面打开期间按时间自动切换；不改后端、买入逻辑、提醒弹窗的跳转。
- 不改周末与 09:15 前的默认行为；不做节假日判断。

**反目标**
- 用户保存的展开偏好被时段默认值悄悄改写。
- 用户点开的 `?tab=live` 被收盘后默认值覆盖。
- 竞价窗口之外，页面行为有任何变化。

## 5. 方案对比

| 方案 | 取舍 |
|---|---|
| **A. 进入页面时按时段给默认值（选定）** | 简单、可预期，不覆盖明确选择；已打开的页面不会自己变 |
| B. 随时间实时切换布局 | 盯盘中页面自己变化，容易误操作 |
| C. 可配置的时段方案 | 现在没有这个需求，违反“不加未被要求的配置” |

## 6. 已知限制

- 竞价前窗口里，“昨日首板反馈”在“今日盯盘”页签内；切到别的页签再切回来，它会按竞价前默认重新展开（页面挂载时的时段不变）。你在窗口内手动收起的状态在切换页签后不保留。

## 7. 验证

- 时段判断的纯函数测试（边界、周末、跨时区的时间戳）；`YesterdayFeedback` 竞价前默认与偏好不被改写的测试；页面级测试（收盘后默认标签、地址参数优先、竞价前展开）。
- `pnpm exec vitest run src/custom/first-board`、`pnpm build`。
- 当前时间不在上述时段内，浏览器里只能确认默认行为未变；各时段的实际表现靠测试验证。
