# 首板候选表合并价格列并补上成交额、流通市值（设计，已确认）

> 日期 2026-11-21。状态：用户已确认方案。后端只新增一个展示字段，不改任何判定；前端调整候选表列。

## 1. 目的

候选表有 11 列，价格相关的占 3 列（现价、涨幅、距涨停），而首板判断依赖的成交额和流通市值一列都没有：成交额只在依据展开区里，流通市值根本没有。目标：合并价格列腾出位置，补上这两个数字。

## 2. 行为

- **合并“现价”和“涨幅”为一列**，两行显示：上面现价，下面涨幅，沿用现有的红涨绿跌着色和缺失规则（价格缺失时整格中性、显示“—”）。表头里仍有两个独立的排序按钮，分别是“现价”“涨幅”，排序行为与现在完全一致（按钮的可访问名称仍是“按现价排序”“按涨幅排序”）。
- **“距涨停”保持单独一列**。
- **新增“成交额 / 流通市值”一列**，两行显示：上面成交额，下面流通市值，用现有的 `fmtBigNum` 显示（亿、万）；缺失显示“—”，不显示 0。表头里有两个排序按钮“成交额”“流通市值”（“按成交额排序”“按流通市值排序”）。两行各带悬停说明（成交额、流通市值）。
- 列数不变，仍是 11 列（合并两列、新增一列）；证据展开行等用到总列数的地方继续使用显示列数。
- **后端**：每个候选行新增 `float_cap`（元）：`现价 × 流通股本`，价格或流通股本缺失、非有限数或非正时为 `null`。成交额沿用 `evidence.amount`，不新增字段。该字段只作展示，不参与任何判定。

## 3. 目标、非目标、反目标

**目标**：不增加列数，把盘子大小和成交活跃度放到表里，且所有已有的排序能力保留。

**非目标**
- 不加流通市值或成交额的筛选；不加换手率列（它已在依据展开区里）。
- 不改后端的任何判定，不改 `can_buy`、阻断原因、建议金额。
- 不重新定义“距涨停”。

**反目标**
- 合并后丢失“按现价排序”或“按涨幅排序”。
- 缺失的成交额或流通市值显示为 0。
- 流通股本单位不一致导致市值数量级错误。

## 4. 方案对比

| 方案 | 取舍 |
|---|---|
| **A. 合并现价和涨幅，两列内都保留各自排序按钮（选定）** | 列数不增加，排序能力不丢；表头略挤 |
| B. 新增两列，不合并 | 最简单；表更宽，已有最小宽度 1040px 容易横向滚动 |
| C. 把价格、涨幅、距涨停三列合并成一格 | 最省位置；距涨停是临板判断的关键，不该藏进去 |

## 5. 我定的选择（请核对）

1. 流通市值用“当前价 × 流通股本”，流通股本取后端已有的维表（龙头、中军判定在用的同一份）；该数据源缺流通股本时整列显示“—”。
2. 成交额、流通市值的两个排序按钮默认不选中，缺失值排在最后（沿用现有排序规则）。
3. 两行里第二行用次要文字色，靠悬停说明和表头区分含义。
