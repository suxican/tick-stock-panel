# 阶段 3 C 包：猫爪题材归因接入主线与首板（设计，待拍板）

> 依据：规划 3.4、4.1、4.2、13 节。日期 2026-11-20（专业版 Key，小样本实测，未打印 Key）。
> 状态：**实测完成，等待用户对第 4 节口径问题拍板后再实现。**

## 1. 实测结论

### 1.1 `theme_reason`（板块原因）

- 必填参数 `source`，只支持 `xgb`（选股宝）、`jygs`（韭菜公社），可带 `tradedate`；不带则取当日。
- 字段：`tradedate`、`source`、`symbol`（**该来源自己的题材 ID**，如 `1132j`、`16950418x`，不是同花顺/精选板块代码）、`name`、`reason`。**没有更新时间字段。**
- 历史：2026-01-05 起均有数据（每日 xgb 10–30 条、jygs 6–14 条），当日盘中即有且随时间补齐（2026-11-20 收盘后 xgb 13、jygs 6）。可按日回查，**不需要留档**。
- 题材 ID 与本地板块目录、猫爪精选板块都不同源，只能靠**名称**对接，且名称不保证与同花顺概念同名（如「养猪」「AI硬件」）。

### 1.2 `hotstock`（热榜）——是**个股**热榜，不是题材热榜

- 参数 `type` 为 `来源&榜单`，实测有数据的只有 `ths&normal`（同花顺人气，100 只）、`dfcf&renqi`（东财人气，100 只）、`ths&trend`（同花顺飙升，16–76 只）；其余组合返回 0 行（规划所称 15 种榜单未能枚举，无文档，不再盲猜）。
- 不带 `tradedate`：返回 `s/n/pc`（代码、名称、涨幅），**无排名、无时间戳**，按行序即排名。带 `tradedate`：返回 `s/rank/tradedate/type`，**无名称、无时间戳**。
- 历史起点：2026-06-01 查不到，2026-07-01 起有（与「约 2026-06/07」一致）。
- 与首板现有「个股人气」（zzshare 首页的同花顺热榜 `ths_hot_top`）同属个股排名，`ths&normal` 是它的第二来源；`dfcf&renqi` 是新增的东财口径。

### 1.3 `theme_hot_kp`（板块热搜）

- 参数必须为空，**只返回最新榜单**（带日期报 422），当前 5 行：`rank/theme_symbol/theme_name/updated_at`，`date` 为空。`updated_at` 实测 16:31（盘后），**可作 `available_at`**。
- 题材代码是猫爪热搜自己的体系（`801001` 芯片），与精选板块 `801001k` 同号去 k，疑似同源，**待确认**，不能据此假定可 join。
- 已在每日盘后留档，现可读历史（从留档日起）。

### 1.4 `jx-long`（龙排名）——**没有同名接口**

- 以 `jx_long / jx-long / themelong_jx / jxlong / theme_long_jx / long_jx / themerank_jx` 调用全部返回「不支持的 apiname」(1004)。此前核对表把 `thememembers_jx` 标作「龙排名」：实测它返回 `{theme_symbol, symbols}`，276 个板块的 `symbols` **全部按代码升序**，没有排名字段。
- `themeauthentic_jx`（最正宗，150 个板块）的 `symbols` **不是**升序（113/150 乱序），疑似按龙/正宗度排序。用 11-20 全市场快照检验（51 个有效板块）：前 3 只平均涨幅 −2.21%，其余 −4.04%，末 3 只 −4.83%，前 3 只成交额中位约为其余的 1.97 倍——**顺序有明显「越靠前越强/越活跃」的单调性，但无官方文档证明它就是龙排名**。
- 结论：**没有可引用的官方龙排名**；只有「正宗名单的顺序」这一未经证实的线索。留档 `jx_authentic` 的 parquet 保留行序，无需改留档格式即可事后取序。

### 1.5 个股涨停原因 vs zzshare（首板原因是当天新写还是沿用）

- zzshare 盘后归因（`zzshare_limit_reasons`）的 `reason` 与猫爪 `screening` 的 **开盘啦（kpl）同源**：2026-11-17 两边都有的 39 只中，33 只 zzshare 原因以猫爪 kpl 文本开头，其余附带韭菜公社/选股宝详情。**两者不是独立证据**，猫爪只是更全（11-17：猫爪 50 只 vs zzshare 39 只，多出 11 只，zzshare 缺的并非无原因）。
- 连续两日都涨停的个股：韭菜公社 jygs、选股宝 xgb 基本沿用（11-17→11-18：12/15、14/15 相同；11-18→11-19：9/9、9/9），开盘啦 kpl 会改写或缺失（6/15 相同，其余多为改写，3 只次日为空）。**连板沿用，与规划 13 节一致。**
- 首板个股前一日没有涨停，按定义原因是当天新写；但本地只有 4 天猫爪归因留档，无法检验「隔多日再次首板是否沿用旧原因」，**此结论只能标注为未证实**。
- 另一个事实：首板页展示的是**尚未涨停的候选**，个股涨停原因只在涨停后才有，不能作为候选的归因；候选的题材归因应来自板块层（`theme_reason` 与热搜）。

## 2. 目标与不做

目标
1. 主线（概念/行业分析页）：新增「题材归因」只读区，列当日选股宝/韭菜公社的板块原因，按名称精确匹配到排名靠前的概念时在该概念行旁提示；另显示板块热搜前 5。
2. 首板：个股人气增加第二、三来源（东财人气、同花顺飙升）作为补充证据，并显示所属题材在板块热搜中的名次（名称精确匹配时）。
3. 所有证据带 `source`、`available_at`（无更新时间的接口只有获取时间，如实标注「获取」），来源缺失显示「来源不可用」。

不做
- 不替换 zzshare，不改变主线评分、阶段判定、首板优先分和现有候选判定。
- 不展示未经证实的「龙排名」（见问题 1）。
- 不做模糊名称匹配；不枚举 hotstock 未知榜单。

## 3. 方案

### 后端
| 模块 | 内容 |
| --- | --- |
| `plugins/meoz/provider.py` | 新增 `get_theme_reasons(day)`（xgb+jygs 两次请求，统一为 `{source, theme_id, name, reason}`）、`get_hot_stocks(type, day=None)`（统一为 `{symbol, rank, name?, pct?}`）、`get_theme_hot()`。 |

| `services/meoz_hot_rank.py`（新） | `hotstock` 三个榜单与 `theme_hot_kp` 的实时读取（60 秒缓存，不落盘，记录 `fetched_at`）；`theme_hot_kp` 历史从 `meoz_archive/theme_hot_kp` 读取。 |
| `custom/meoz_reasons.py` | 增加 `GET /api/meoz/theme-reasons?date=`、`GET /api/meoz/hot-rank`；错误映射沿用 422/503/502。 |

- `api.ts`、`queryKeys.ts`、`lib/useMeozThemeReasons.ts`（沿用 `useMeozReasons` 的盘中 60 秒刷新、定版后停止、503/502 静默为空）。
- 概念分析页：一个折叠面板「题材归因 · 选股宝/韭菜公社」，默认收起，头部只显示条数与来源状态；热搜前 5 用小徽章。
- 首板 `PriorityCell` 展开区：在现有「同花顺当时人气第 N 名」下追加一行东财人气/同花顺飙升名次与获取时间。**不进入优先分**。
- 缺数据：显示「来源不可用」，不显示为「无题材/未上榜」；未上榜与不可用用不同文案。

## 4. 需要拍板的口径问题

1. **龙排名**：没有官方接口。建议**本包不做龙排名**，只在 `themeauthentic_jx` 行序上做一次更大样本验证后再决定；你也可以让我现在就以「正宗名单前 3 只（顺序推断，未证实）」标注显示。
2. **名称对接**：选股宝/韭菜公社题材与同花顺概念名称不同。建议只做**精确同名**匹配，其余只在面板中单独列出；是否接受（不做别名表/模糊匹配）？
3. **hotstock 用途**：因无时间戳，不满足首板雷达的 10 分钟新鲜度门槛，建议**只作展示证据，不进入优先分**；若希望进入评分，需另立任务并先做离线验证。
4. **历史回看**：`theme_reason` 可回查到 2026-01；`hotstock` 到 2026-07；`theme_hot_kp` 只从留档日起。建议主线页的归因面板随页面日期选择回看，`hotstock` 与热搜只显示当日实时（首板是实时功能），是否接受？
5. **首板个股涨停原因**：因候选未涨停，建议不在首板候选表显示个股涨停原因（连板梯队页已有）。是否同意？
6. **展示位置**：概念分析页是否就是你所说的「主线识别」入口？还是要放在其他页面（如市场环境/看板）？

## 5. 剩余风险

- `theme_reason` 与 `theme_hot_kp` 无官方字段文档，题材 ID 对接依赖名称。
- `hotstock` 的榜单枚举不全，live 与历史返回字段不同（live 无排名字段，以行序为名次）。
- 盘中 `screening`、`thememinute_jx` 偶发 502（规划 13 节），新增读取需重试；本包新接口 502 行为未在盘中实测。
- 首板「隔日再首板是否沿用旧原因」本地样本不足，未证实。
