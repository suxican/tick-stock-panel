# 持仓做T / 持仓分析与计划：猫爪数据阶段 1 设计

> 依据：`docs/猫爪数据对接/猫爪数据对接规划.md` 第 11 节（11.5 阶段 1、11.6 决策 1–3）、第 12–13 节修订。
> 日期：2026-11-19。范围：两个功能的阶段 1 一起做。

## 1. 目的

- **做T**：现在没有任何数据源提供 `trade_status`，所以每只持仓都提示「数据源未提供可核验的证券交易状态」并暂停。涨跌停价只认实时报价自带的字段，不读已经落盘的交易所价。阶段 1 要让大部分持仓能正常评估。
- **持仓分析**：现在没有风险状态。阶段 1 新增 ST、停牌两类风险，命中时先提示，确认后才允许采纳（决策 2）。

## 2. 目标、非目标与反目标

**目标**
1. 新增按日的停牌名单 `suspensions`，接入方式与 `st_status` 相同（能力路由、盘前同步、落盘、读取）。
2. 做T 的涨跌停价改为三级来源：先用实时报价，再用当日交易所价，最后用本地理论价（理论价只作观察）。
3. 做T 新增日级交易状态：当日停牌名单已同步，且该股不在名单中，就判为可交易。按决策 1，这时允许建计划。
4. 做T 新增「疑似盘中停牌」提示：连续竞价时段内买一、卖一同时为空。
5. 持仓分析每行新增风险状态（ST、停牌、来源不可用）。采纳时必须逐条确认；服务端会重新核对，风险有变化时返回冲突。

**非目标（留到阶段 2 及以后）**
- 不做重点监控名单和严重异动预测。这两类数据已有盘后留档，但规划把它们排在阶段 2。
- 不做资金证据、业绩事件、公司行动。
- 不改 depth5 兜底，也不改实时行情的路由。

**反目标（出现以下任意一种，即使功能能跑也算失败）**
- 缺数据时被当作「可交易」或「无风险」。未知必须显示为未知，并保持暂停，或要求用户确认。
- 用接收时间冒充市场时间。
- 采纳时用户确认的是旧风险，而当前风险已经变化。

## 3. 约束

- 遵守 CONTRIBUTING §3 数据契约、§4 插件与能力路由契约、§7 信息精简。
- 猫爪字段不直接传到业务层，必须先转成 `data_providers/schemas.py` 中源中立的契约。
- 读取方只有在 `market_reference.enable_reader` 启用后才读落盘数据；未启用时（含单测）保持现状。
- 不提交 `data/`；Key 不落盘、不打印。

## 4. 方案比较

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 盘前按日落盘、盘中读文件（采用）** | 复用 `market_reference`：09:05 盘前同步涨跌停价、ST、停牌名单，做T 和持仓分析读当日文件 | 和现有 enriched、回测共用同一份数据；盘中不额外消耗调用；回放可追溯。缺点：盘中新出的停牌要等第二天才能体现，由「疑似盘中停牌」补位 |
| B. 盘中每轮调 `screening` | 每轮行情请求一次全市场选股接口 | 数据最新，但每轮多一次调用，还会让做T 直接依赖猫爪，违反「业务层不认厂商」原则 |
| C. 只从实时行情推断 | 不新增数据集，用「有价有量」推断可交易 | 违反契约「不能因有价有量就推断可交易」，排除 |

## 5. 设计

### 5.1 数据层：新增 `suspensions` 能力

- **契约**（`schemas.py`）：`SUSPENSION_SCHEMA = {date, symbol, timing: String(可空), source}`。
  - 只收停牌行（`suspend_type == "S"`）。
  - `timing` 为空表示全天停牌；有值表示部分时段停牌。
- **猫爪适配**（`plugins/meoz/provider.py`）：新增 `get_suspensions(day)`。
  - 用 `startdate=enddate=day` 查询 `suspend` 接口；只传 `tradedate` 会被截断。
  - 用 `_full_symbol` 补全代码后缀；`plugin.yaml` 的 `datasets` 加上 `suspensions`。
- **能力注册**：照搬 `st_status` 的所有接入点，包括 `capabilities.py`、`preferences.py`、`api/settings.py`、`upgrade_guard.py`、`ext_config_transfer.py`、前端 `provider-routing.ts` 和 `DataSources.tsx`。默认源为 `meoz`，`tf_tier=None`。
- **同步**（`services/market_reference.py`）：
  - `DATASETS` 新增 `suspensions`，最早日期 2020-01-02，可取时间 09:00。
  - 盘前任务改为 09:05 和 09:20 各跑一次；第二次用来补第一次的失败，已有文件会跳过。
- **空表不落盘**：`_validate` 遇到空表报错的规则保持不变，所以当天没有任何停牌时也不会落盘，读取方会视为「未知」。
  - 这是保守取舍：全市场没有停牌的交易日极少，代价只是当天暂停判断。
  - 「盘前是否已经能取到停牌名单」还没有实测，上线后要观察。
- **读取**：新增 `day_reference(day) -> {price_limits, st, suspensions}`。
  - 每项是 `{symbol: …}`；当天文件不存在时为 `None`，表示未知，而不是「没有」。
  - 进程内按 `(day, 文件 mtime)` 缓存。

### 5.2 做T（`services/position_t_market.py::_quote`）

- **涨跌停价**：
  - 实时报价带有效的 `limit_up_price` 和 `limit_down_price` 时，用报价的值。
  - 否则当日交易所价存在时，用交易所价，并标记 `price_limit_source="exchange_daily"`。
  - 交易所价 `no_limit=True` 时，沿用现有提示「当日无涨跌幅限制，首版暂停新建计划」。
  - 以上都没有时，保持现状：使用理论价，并提示「理论价仅作观察」。
- **交易状态**：新增 `trade_status_basis: intraday | daily | none`。
  - 报价或盘口明确给出状态时，直接采用，basis 为 `intraday`。
  - 当日停牌名单已落盘时：
    - 该股在名单中，判为 `suspended`；部分时段停牌也一样，这是保守处理。
    - 该股不在名单中，且是交易日、已上市，判为 `trading`，basis 为 `daily`。
    - 证据中记录「盘中状态未确认」，随 quote 写入 `signal_history`。
  - 名单不存在时为 `unknown`，与现状相同，显示原提示并暂停。
- **疑似盘中停牌**：连续竞价时段内，盘口买一、卖一同时为空或为 0 时，加一条 data_error「买卖一均为空，疑似盘中停牌」。
  - 现有盘口校验已经会因此暂停；这条只是让原因明确。
  - 不另外跟踪成交量变化：封涨停、封跌停时只会有一边为空，两边同时为空几乎只发生在停牌时。
- **自动模拟账户**：同样适用决策 1；风险退出逻辑不变。

### 5.3 持仓分析（`services/holding_analysis.py`）

- **风险状态字段**：每行新增 `risk_status = {items, as_of, fingerprint}`。
  - `items` 的每一项包含 `{id, label, detail, source}`，`id` 取值为：
    - `st`：风险警示，`detail` 为 ST 类型；
    - `suspended`：停牌，`detail` 为全天或部分时段；
    - `st_unknown`：ST 名单不可用；
    - `suspension_unknown`：停牌名单不可用。
  - `fingerprint` 是 items 的稳定哈希。
- **核对日期**：取研究时点所在的最近一个交易日（≤ 今天）对应的名单文件，并在 `as_of` 中写明日期。
- **不影响研究结论**：风险状态不改变 `ready`、情景和价位，只是事实证据。AI 解读只能引用程序给出的模板文字。
- **采纳接口**（`POST /api/holding-analysis/plans`）新增 `acknowledged_risks: list[str]`，默认为空。
  - 服务端用相同函数重新计算该行当前的风险。
  - 当前风险与报告不一致时返回 409「风险状态已变化，请重新分析」。
  - 用户确认的项没有完全覆盖当前风险时返回 409「请先确认全部风险」。
  - 计划中保存 `acknowledged_risks` 和 `risks_acknowledged_at`。
- **采纳后风险变化**：
  - 概览接口为已采纳计划重新计算风险；与采纳时不同就显示警示，但不自动作废计划。
  - 按规划的建议，把「风险状态变化」并入现有的提醒暂停条件，和除权基准暂停一样处理。

### 5.4 前端

遵循 CONTRIBUTING §7：主列表只显示一个标签，详情放在展开区。

- **`HoldingAnalysis.tsx`**：
  - 报告行显示一个标签：有命中时为「风险 N」，只有未知项时为「风险未知」。
  - 展开后列出每项明细、来源和截止日期。
  - 有风险时点「采纳」，会弹出确认框，逐条勾选「已知悉」后才能提交。
  - 已采纳计划的风险发生变化时，显示警示条。
- **`PositionTMonitor.tsx`**：只在信号详情展开区显示「日级状态已确认，盘中状态未确认」和涨跌停价来源；候选行不新增信息。

```
持仓行:  600xxx 某某股份  -3.2%  趋势:震荡  [风险 1]  [采纳]
展开区:  风险状态（截至 2026-11-19，来源：猫爪）
         · 风险警示：*ST
采纳确认: ☐ 已知悉：风险警示 *ST
         [取消] [确认采纳]
```

## 6. 验证

- **后端单测**：
  - 猫爪停复牌解析：只保留 S，正确处理时段和代码后缀。
  - `day_reference`：文件缺失时为 `None`，有文件时正确读取。
  - `_quote` 的各种情况：三级涨跌停价、四种状态来源、疑似停牌。
  - 持仓分析风险项：命中、未知、无风险。
  - 采纳接口：未确认、部分确认、风险变化返回 409、全部确认后成功。
  - 能力矩阵：包含新增的 `suspensions`。
- **前端测试**：风险标签、确认框勾选后才能提交、已采纳计划的风险变化警示。
- **数据源相关**：按 CONTRIBUTING §9 跑相应测试。

## 8. 遗留风险

- 停牌名单盘前能否取到还没有实测；取不到时当天做T 保持暂停，即保持现状。
- 盘中新出的临时停牌只能靠「买卖一同时为空」发现，可能有一两轮延迟；而这期间盘口校验本来就会暂停判断。
