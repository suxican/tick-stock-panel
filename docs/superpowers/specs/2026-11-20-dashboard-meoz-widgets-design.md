# 看板新增「实时热搜 / 最强风口 / 新闻」组件设计

日期：2026-11-20　状态：待审阅

## 1. 意图

在【看板】页增加三个组件，对应猫爪网站「三方数据」下的「实时热搜」「最强风口」和「资讯 → 新闻」。目的是让盘中看板直接呈现市场关注度、资金强度和最新消息，不用再跳转到别的页面。

## 2. 目标 / 非目标 / 反目标

目标
- 三个组件可在编辑态「添加组件」里摆放、拖拽、调宽高，布局随用户保存。
- 个股点击沿用 `ctx.openStock`，保持「上一只/下一只」导航。
- 数据来源不可用、数据过期、回看历史日时，如实提示，不展示误导数据。

非目标
- 不改 `DEFAULT_LAYOUT`，老用户布局不受影响。
- 不做新闻与个股/题材的关联（上游没有该字段，不自行匹配）。
- 不让这三类数据参与首板优先分、候选判定、主线评分。
- 不落盘新闻正文，不接入 AI 上下文。
- 不新增完整页面。右上角的跳转入口只在已有页面存在时才放。

反目标（做出来也算失败）
- 把今天的热搜或新闻当成历史日的数据展示。
- 来源失败被显示成「空榜」「无新闻」。
- 三个组件把上游请求频率推高到触发 429。

## 3. 探测结论（2026-11-20，真实 Key，只读）

| 接口 | 结论 |
|---|---|
| `fengk_kp` | 返回个股榜，约 30 条，已按 `strength` 降序。字段：`symbol, name, strength, pct_chg(百分数), main_net_amount, main_buy_amount, main_sell_amount, signal_time(秒级时间戳), selected_themes`。题材标签不全（样本 12/30 为空），多个题材用「、」分隔。`tradedate` 参数有效（返回对应日 `signal_time`），`date` 参数无效。 |
| `news` | 一次最多 100 条，只有当天。字段：`published_at, display_at, time_label, source, source_name, title, summary, url, image, rank, source_id, item_type, updated_at`。`limit` 有效，`source` 和 `date` 无效。来源只有 3 个（第一财经头条、财联社头条、财联社 A 股）。`summary` 约 35%、`published_at` 约 19% 为空，没有个股或题材关联。 |
| `hotstock` / `theme_hot_kp` | 已接入（`meoz_hot_rank.py`），无需再探测。 |

需要写进 `docs/猫爪数据对接/接口可用性与口径核对表.md`：`fengk_kp` 一行补上述字段和历史能力，新增 `news` 一行。

## 4. 约束

- 现有契约：涨跌幅在前端展示用百分数；`fengk_kp` 的 `pct_chg` 是百分数，`MeozHotStock.pct_chg` 已是小数制，不能混用，见 CONTRIBUTING §3。
- 时间：`signal_time` 是时间戳，转北京时间展示。新闻的 `display_at` 没有时区，按北京时间处理（这是推断，需在实现时对照 `time_label` 核对）。主机时钟不是北京时间，不得用主机本地时间格式化。
- 上游节流：`MeozClient` 串行节流；组件各自后端缓存 60 秒。
- 猫爪插件未加载或 Key 未配置时，三个组件显示「来源不可用」，不报错、不刷红。
- 实时数据不回看：热搜和新闻没有历史。

## 5. 方案选择

后端接入：
- **A（采用）**：先探测，再按真实字段设计。已完成探测。
- B（否决）：先按 `hotstock` 模式写骨架、字段留空。字段对不上要返工两遍。

组件取数：
- **采用**：每个组件自己取数（`useQuery`），参照 `BellwetherWidget`，不塞进 `OverviewMarket`。避免大盘接口被慢上游拖累。
- 否决：并入 `overview-market`。会让猫爪超时影响整个看板首屏。

## 6. 设计

### 6.1 后端（新增两个服务和路由，热搜沿用）

- `app/services/meoz_strongest_vent.py`：`read(trade_date: date | None)`。`None` 表示实时，缓存 60 秒；传日期则按 `tradedate` 查询，历史日不可变，进程内缓存即可，不落盘。
- `app/services/meoz_news.py`：`read(limit=50)`，缓存 60 秒，只保留 `display_at, time_label, source, source_name, title, summary, url, item_type` 字段，丢弃图片等无关字段。
- Provider 增加 `get_strongest_vent(day)` 和 `get_news(limit)`，沿用 `_query_retry`。
- 路由加在 `meoz_reasons.py`：`GET /api/meoz/strongest-vent?date=`、`GET /api/meoz/news?limit=`，错误映射沿用现有：未就绪 503、日期口径 422、上游异常 502。
- 字段规整：`strength` 转数值，`pct_chg` 转浮点，`signal_time` 转 ISO 北京时间，题材按「、」拆成数组，空值为空数组。
- 空结果与失败区分：返回 `available` 和 `rows`，与 `meoz_hot_rank` 一致。

### 6.2 前端

- `WidgetType` 增加 `'hot-search' | 'strongest-vent' | 'news'`；`WIDGET_DEFS` 注册，均为单实例（`Dashboard.tsx` 已按类型去重）。
- 新文件放在 `components/dashboard/`：`HotSearchWidget.tsx`、`StrongestVentWidget.tsx`、`NewsWidget.tsx`，各自带测试。
- `api.ts` 增加类型与 `meozStrongestVent`、`meozNews`；`QK` 增加对应键。
- `WidgetCtx` 增加看板选中的交易日（组件需要它调用最强风口历史），不要用 `isLatestDate` 反推日期。
- 默认尺寸：热搜 4×10（最小 3×7），风口 4×9（最小 3×7），新闻 4×12（最小 3×8）。
- 数据更新：盘中 60 秒轮询，页面不可见时不轮询；保留上一份有效数据，失败时顶部显示「来源不可用」。

### 6.3 三个组件的 UI

通用：`sectionCard` + `SectionTitle`（图标、标题、右侧更新时间）。红涨绿跌用现有 `priceColorClass`。窄宽度标题行允许换行。编辑态组件内部不可点（框架已处理）。

**实时热搜**
```
┌ 🔥 实时热搜          14:32 · 60s刷新 ┐
│ [同花顺人气] 东财人气  同花顺飙升     │  分段切换，选择随实例参数保存
│  1  中通客车   +10.0%                 │
│  2  金融街     +9.98%                 │
└───────────────────────────────────────┘
```
- 复用 `useMeozHotRank`，不新增接口。「板块热搜」作为第四个分段，行显示排名和板块名（无涨幅）。
- 榜单失败显示「来源不可用」，与真正的空榜区分。
- 热搜无历史：回看历史日时显示「热搜仅实时数据」，不显示榜单。
- 取数时间来自 `fetched_at`；板块热搜另显示上游更新时间。

**最强风口**
```
┌ 🧭 最强风口       信号 10:06 · 30只 ┐
│ 1 冰山冷热  +10.03%  强度4893  +9.7亿 │
│   [并购重组]                          │
│ 2 超声电子  +9.98%   强度4181  +…     │
└───────────────────────────────────────┘
```
- 默认显示：排名、名称、涨幅、强度、主力净额；题材标签一行，空则不占位。
- 点击行打开个股预览；点击题材标签不跳转（没有稳定的题材代码）。
- 主力买入、卖出额作为悬停提示，不占主界面。
- 当日实时模式：60 秒轮询；历史日：带 `tradedate` 查询，标题显示「回看 YYYY-MM-DD」，不轮询。
- 历史日取数失败显示「来源不可用」，取到空结果显示「该日无数据」，两者都不回退到实时数据。
- 历史深度未测（核对表写「约 2026-09 起」），超出范围时按空数据提示。

**新闻**
```
┌ 📰 新闻     全部｜财联社｜第一财经     ┐
│ 21:01 第一财经 逼近20万亿元！详解前10月…│
│ 20:59 财联社   …                        │
└─────────────────────────────────────────┘
```
- 纯时间线：时间、来源、标题。标题在新标签页打开原文，使用 `rel="noopener noreferrer"`。
- 摘要按需展开（点击行末箭头），没有摘要的行不显示箭头。
- 来源筛选在前端做，选择随实例参数保存。
- 取最新 50 条；按 `display_at` 倒序，同一时间保持上游顺序。
- 回看历史日显示「新闻仅实时数据」。

## 7. 测试与验证

- 后端：服务单测，覆盖字段规整（类型、空题材、时间戳转北京时间）、空结果与失败区分、缓存命中，路由错误映射。不用真实 Key。
- 前端：三个组件各自的渲染、来源不可用、回看历史日、窄宽度、交互（分段切换、来源筛选、展开摘要）。`registry` 和 `layout` 测试补新类型。
- 页面验证：按已有约定用临时数据目录启动，确认不会写入真实 `data/`。
- 范围：运行 CONTRIBUTING §9 对应的后端与前端测试，以及 TypeScript 检查。
- 不修改已有测试的断言来迁就新组件。

## 9. 待决项（留给实现者）

- 新闻 `display_at` 的时区需对照 `time_label` 确认为北京时间。
- `fengk_kp` 历史最远可回溯到哪天，由实现时探测，并据此决定回看日期的提示文案。
- 回看日选择器的可选范围是否要限制到最强风口有数据的区间，默认不限制，仅提示。
- 新闻来源集合只有 3 个，筛选项按返回结果动态生成，不写死。
- 新增文件按仓库既有的 CRLF 约定保存。

## 10. 风险

- 猫爪新闻的使用条款未核实，展示标题和链接外的内容（正文、图片）不保存。
- 新闻或风口接口字段将来可能变化，规整函数遇到缺字段时按「来源不可用」处理，而不是抛错。
