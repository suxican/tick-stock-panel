# 市场环境页「环境结论」设计

状态：待审阅 · 2026-11-15

## 1. 意图

用户每天收盘后决定第二天的总仓位上限和打法。系统已经有两条环境轴：环境分（5 档，合并为强 / 震荡 / 弱三档）和资金总量档位（放量 / 平量 / 缩量），并已完成离线验证：资金在情绪之外有稳定增量信息，且不是当日涨跌惯性的替身（见 `docs/market-capital.md`）。

本设计把两条轴交叉成 9 格，让用户为每一格**预设自己的**仓位上限与打法。系统每天只做三件事：定位当天所在的格子、展示用户对这一格的预设、并排展示这一格的历史证据。仓位数字与打法完全来自用户，系统不生成建议。

## 2. 目标、非目标与反目标

**目标**

- 用户可在环境页编辑 9 格预设：仓位上限（0–100%）、打法（多选）、备注。
- 环境页显示"环境结论"卡：当天格子、用户预设、与博弈页市场闸门叠加后的生效上限、这一格的历史证据。
- 校准归档增加每格统计，供证据展示。

**非目标**

- 系统根据校准结果自动生成或调整仓位。
- 复盘页"明日剧本"引用环境结论、"今日执行"统计是否按预设执行（后续另行设计）。
- 首板过滤、博弈页闸门本身的逻辑变化。
- 盘中暂定结论。结论只基于盘后 `regime_history` 的最新一行。

**反目标**（出现即视为失败）

- 用户未设置某格时，页面显示任何默认仓位数字。
- 生效上限高于博弈页当日市场闸门上限。
- 证据样本不足时仍显示均值、比例等数值，而不标明不足。
- 文案出现"建议仓位""推荐打法"等暗示系统给出建议的措辞。

## 3. 约束

- 遵循 `CONTRIBUTING.md`：API 层保持薄；前端请求与类型走 `frontend/src/lib/api.ts`，查询键走 `queryKeys.ts`；历史数据缺字段可读。
- 预设存于用户偏好 `preferences.json`，沿用 `preferences.py` 的读写与原子写入；不新增运行时目录。
- 单位：预设仓位上限以整数百分数存储（`60` 表示 60%）；博弈页 `allocation.total_cap` 为小数制，在后端边界换算并加单位测试。
- 校准归档格式只增不改，旧归档（无 `cells`）照常可读。
- 前端命令只用 `pnpm` / `pnpm exec`；工作区 CRLF。

## 4. 方案取舍

| | 做法 | 结论 |
| --- | --- | --- |
| A | 只给证据，不给数字 | 未选：用户仍需自行换算仓位 |
| **B** | **用户预设每格仓位与打法，系统定位并展示证据** | **用户选定** |
| C | 系统按校准结果自动换算仓位 | 否决：校准只证明全市场次日方向差异，未证明任何仓位映射 |

## 5. 设计

### 5.1 格子

- 情绪三档：`strong`（强势、偏强）、`range`（震荡）、`weak`（偏弱、弱势），与校准 `MATRIX_SENTIMENT` 共用同一映射，不另建副本。
- 资金三档：`capital_volume` 的 `expand` / `flat` / `shrink`。
- 格键：`<情绪>_<资金>`，例如 `strong_expand`。
- `state` 或 `capital_volume` 为空时，当天无格子，结论卡显示原因（"资金档位未计算"或"环境分缺失"），不显示任何预设。

### 5.2 预设（偏好）

偏好键 `env_matrix_plan`：

```json
{
  "strong_expand": {"cap_pct": 70, "styles": ["打板", "半路"], "note": "主线龙头为主"},
  "weak_shrink":   {"cap_pct": 0,  "styles": ["空仓观望"], "note": ""}
}
```

- 未出现的格子视为"未设置"。
- `cap_pct`：0–100 的整数；`styles`：从固定列表多选——`打板`、`半路`、`低吸`、`趋势持股`、`空仓观望`；`note`：最长 60 字。
- 读写函数 `get_env_matrix_plan()` / `set_env_matrix_plan(plan)`：写入时丢弃未知格键、未知打法和越界数值；整表替换，不做部分合并。
- 接口：`GET /api/preferences/env-matrix-plan`、`PUT /api/preferences/env-matrix-plan`。

### 5.3 每格历史证据（校准归档）

`market_game_credibility.summarize` 在返回中新增 `cells`：

```json
"cells": {
  "strong_expand": {
    "all":   {"n": 238, "mean": 0.0036, "positive_rate": 0.58, "p10": -0.012},
    "train": {"n": 91,  "mean": 0.0044, "positive_rate": 0.60, "p10": -0.011},
    "test":  {"n": 147, "mean": 0.0031, "positive_rate": 0.57, "p10": -0.013}
  }
}
```

- 数据来自校准结果中 `shadow:matrix:<格>` 及其 `@train` / `@test` 分组的 `ew_1` 汇总（次日全市场等权涨幅，小数制），不重新计算。
- 某段 `n < 30`（沿用 `MIN_DAYS`）时，该段只保留 `n`，其余字段为 null。
- 旧归档无 `cells` 时，前端显示"证据待校准"，并提示运行校准命令。

### 5.4 结论接口

新增 `GET /api/regime/conclusion`，返回最新一个交易日的结论：

```json
{
  "date": "2026-11-13",
  "cell": "strong_expand",
  "sentiment": "strong", "volume": "expand",
  "missing_reason": null,
  "plan": {"cap_pct": 70, "styles": ["打板", "半路"], "note": "主线龙头为主"},
  "gate": {"cap_pct": 50, "report_id": "…", "as_of": "2026-11-13"},
  "effective_cap_pct": 50,
  "limited_by": "gate",
  "evidence": { "all": {…}, "train": {…}, "test": {…} },
  "evidence_as_of": "2026-11-16T08:12:44+08:00"
}
```

- `plan`：该格未设置时为 null，`effective_cap_pct` 也为 null。
- `gate`：取博弈页报告中 `as_of` 等于 `date` 的报告；有多份时取 `created_at` 最新的一份，读取 `allocation.total_cap` 换算为百分数。没有当日报告时为 null。
- `effective_cap_pct`：预设与闸门都有时取小值；只有预设时取预设，`limited_by` 为 `"plan"`，并标记"未叠加闸门"。
- `limited_by`：`"plan"` / `"gate"` / `"both"`（两者相等）/ null。
- `evidence`：最新校准归档 `cells` 中该格的统计；无归档或无 `cells` 时为 null。
- 计算放在新服务模块 `backend/app/services/environment_conclusion.py`；API 层只做转发。

### 5.5 环境页

"资金"卡之后新增"环境结论"卡，放在情绪周期页签内：

```
环境结论  2026-11-13                          [编辑预设]
强 · 放量
仓位上限 50%   （我的预设 70%，被市场闸门 50% 限制）
打法  打板 · 半路
备注  主线龙头为主
─────────────────────────────
本格历史（次日全市场等权）  238 天
均值 +0.36% · 上涨比例 58% · 第10百分位 -1.20%
训练段 +0.44% · 测试段 +0.31%
```

- 未设置：仓位与打法行显示"未设置"，主操作为"编辑预设"。
- 闸门缺失：上限行注明"当日未生成盘后计划，未叠加市场闸门"。
- 无格子：只显示缺失原因。
- 证据样本不足：显示"样本不足（n 天）"，不显示数值。
- 证据标题悬浮说明："全市场次日等权涨幅，样本内统计，不是个股或可成交收益。"

"编辑预设"打开 3×3 网格弹窗：行为强 / 震荡 / 弱，列为放量 / 平量 / 缩量。每格可填仓位上限、勾选打法、写备注；每格旁显示该格历史天数，方便用户知道哪些格子常见。保存时整表提交；关闭不保存时丢弃修改。

## 6. 验证

- `preferences`：合法写入往返；未知格键、未知打法、越界 `cap_pct`、超长备注被清洗；空表可写入。
- `environment_conclusion`：
  - 9 格定位正确；`state` 或 `capital_volume` 为空时 `missing_reason` 正确。
  - 预设与闸门取小值；只有预设；只有闸门（`effective_cap_pct` 为 null）；两者相等时 `limited_by="both"`。
  - 闸门只取同日报告；同日多份取最新。
  - `total_cap` 小数到百分数的换算（`0.5` → `50`）。
- `summarize`：`cells` 统计正确；不足 30 天的段数值为 null；旧结果无矩阵分组时 `cells` 为空。
- API：`/api/regime/conclusion` 在无环境历史、无预设、无闸门、无归档时都返回 200 且字段为 null，不报错。
- 前端：`Regime.test.tsx` 覆盖已设置、未设置、闸门限制、无格子、证据不足；编辑弹窗保存与取消；`pnpm build`。
- 页面：临时数据目录实测，桌面与 390 像素窄屏、深浅主题。

## 7. 我自行决定、未经用户确认的事项

- 打法固定为 5 个选项可多选，外加备注；不用自由文本，便于以后统计是否按预设执行。
- 未设置的格子不给任何默认值。
- 证据用"均值、上涨比例、第 10 百分位、训练与测试段均值"，第 10 百分位表示较差日子的大致水平。
- 结论卡放在情绪周期页签、资金卡之后；看板不显示。
- 博弈页闸门只取同日报告；博弈页计划需用户手动生成，因此很多天会显示"未叠加市场闸门"。
