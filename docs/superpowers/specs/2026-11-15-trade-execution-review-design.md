# 复盘「今日执行」与交易记录 设计

状态：待审阅 · 2026-11-15

## 1. 意图

现有 AI 复盘已覆盖市场环境、涨停主线、情绪周期和明日剧本，并由系统核验剧本是否命中。它核验的是"我对市场的判断"，不核验"我自己的交易"：买入有没有依据、止损有没有执行、哪类交易在赚钱。本设计补上这一块。

数据来源经用户确认为**复用批次提醒**。批次只记买入（`backend/app/strategy/lots.py` 明确"只生成监控规则，不做会计"），卖出后用户只能删除批次，不留痕。因此需要一个"结清"动作来留下卖出记录。

## 2. 目标、非目标与反目标

**目标**

- 结清批次时留下一条交易记录：卖出价、卖出日、归因。
- 复盘快照增加"今日执行"：当日新建批次、当日结清、已触及止损价仍持有的批次、累计统计。全部由程序计算。
- AI 正文对"今日执行"只做解释。

**非目标**

- 部分卖出、加减仓记账。本版只支持整批结清；分批卖出需先把批次拆成两条。
- 手续费、分红、已实现收益的完整会计。
- 读取做 T 账本或模拟盘的成交。
- 由 AI 判断归因。
- 之前讨论的第一期（指标补齐、核验长期保存、复盘页分区）和第三期（仓位闸门、突发热点情景），各自另行设计。

**反目标**（出现即视为失败）

- 批次模块变成记账模块，或"删除批次"的现有行为被改变。
- 数量、成本金额、备注进入发给模型的提示词或外部推送。
- 数据缺失时给出看似确定的结论（例如买入日未知却算出持有天数）。

## 3. 约束

- 遵循 `CONTRIBUTING.md`：API 层保持薄；前端请求与类型走 `frontend/src/lib/api.ts`，查询键走 `queryKeys.ts`；新增运行时目录须同步 `docs/data-directory.md`；历史数据缺字段可读。
- 日期按北京时间和项目交易日历；持有天数按交易日计。
- 价格为用户登记的原始成交价，不做复权换算。
- 涨跌幅口径：记录只存价格，盈亏在读取时计算；对外字段 `pnl_pct` 为**百分数**，与复盘快照现有约定（"百分比字段均为百分数"）一致，边界处加单位测试。
- 前端命令使用 `pnpm` / `pnpm exec`，不用 `npx`。

## 4. 考虑过的做法

| 做法 | 取舍 | 结论 |
| --- | --- | --- |
| A. 在批次上加卖出字段，已卖出的批次保留为"已结清"状态 | 改动最少，但批次列表、派生规则、持仓分析、风向标都要学会跳过已结清批次，且打破"批次不做会计"的边界 | 不采用 |
| B. 新增独立的交易记录，"结清"时把批次冻结成一条记录后按现有逻辑删除批次 | 多一个小模块和目录；批次及其所有消费方不变 | **采用**（用户已确认） |
| C. 不加动作，把"批次被删除"推断为按当日收盘价卖出 | 零操作成本，但卖出价不准、无法区分登记错误与真实卖出、没有归因 | 不采用 |

## 5. 设计

### 5.1 交易记录

新目录 `data/user_data/trade_journal/`，每条记录一个 JSON 文件，沿用 `JsonDefinitionStore`（与批次同款存储契约）。不设条数上限，统计需要长期样本。

记录 id 由批次 id 派生（`tj_<lot_id>`），同一批次重复结清只会覆盖同一条记录。

字段（结清时冻结）：

| 字段 | 说明 |
| --- | --- |
| `id`、`lot_id` | 记录与来源批次 |
| `symbol`、`name` | 代码与当时名称 |
| `qty`、`cost_price`、`buy_date` | 来自批次；`buy_date` 可为空 |
| `target_pct`、`stop_pct` | 来自批次，便于事后对照 |
| `sell_price`、`sell_date` | 用户填写 |
| `reason` | 归因，取值见下 |
| `note` | 可选备注，最长 200 字 |
| `had_invalidation` | 结清时该股票在「持仓分析与计划」中是否已登记失效条件 |
| `buy_phase` | 买入日的情绪周期阶段（取自 regime 历史）；买入日未知或无数据时为空 |
| `hold_days` | 买入日到卖出日的交易日数；任一日期缺失或日历不覆盖时为空 |
| `created_at` | 记录时间 |

归因固定五项：`planned_profit` 按计划止盈、`planned_stop` 按计划止损、`early_exit` 提前卖出、`late_stop` 拖延未止损、`unplanned` 计划外交易。

校验：`sell_price` 为正数；`sell_date` 为 `YYYY-MM-DD`，不晚于北京时间今天，且不早于 `buy_date`（已知时）；`reason` 必须是五项之一。非法时返回 400 和中文原因。

### 5.2 接口

- `POST /api/lots/{lot_id}/close`：请求体为 `sell_price`、`sell_date`、`reason`、`note`。先写交易记录，再走现有删除逻辑（批次文件 + 两条派生规则 + 重载引擎）。批次不存在返回 404。写记录成功而删除失败时返回错误，记录保留；用户重试会覆盖同一条记录并再次尝试删除。
- `GET /api/trade-journal`：全部记录（按卖出日倒序，含读取时计算的 `pnl_pct`）与累计统计。
- `DELETE /api/trade-journal/{id}`：删除一条记录，用于纠正误操作。不恢复批次。

现有 `DELETE /api/lots/{lot_id}` 不变，语义为"登记错误，不留记录"。

### 5.3 复盘快照新增 `execution`

在快照装配处新增一节，与 `holdings`、`holdings_check` 并列；无批次且无记录时为 `null`。旧报告没有此字段，前端按缺省处理。快照版本号不变（新增可选字段）。

```
execution: {
  as_of,
  opened:  [{ symbol, name, has_invalidation }],            // 买入日 = 复盘日的批次
  closed:  [{ symbol, name, pnl_pct, hold_days, reason }],  // 卖出日 = 复盘日的记录
  stop_breached: [{ symbol, name, stop_price, close }],     // 见下
  stats: { total, win_rate, payoff_ratio, avg_hold_days,
           by_reason: [...], by_phase: [...] } | null
}
```

- `opened` 同时包含当日买入、当日又结清的记录。
- `stop_breached`：仍未结清、设置了止损比例的批次，复盘日原始收盘价 ≤ 成本 ×（1 − 止损比例）。盘中快照或取不到收盘价时不判定，不列出。
- `stats` 统计卖出日不晚于复盘日的全部记录。`win_rate` 为盈利笔数占比（百分数）；`payoff_ratio` 为平均盈利幅度 ÷ 平均亏损幅度，任一侧无样本时为空。分组项各带样本数。总样本少于 10 笔时前端标注"样本不足"，不隐藏数字。
- 任何一步失败只降级为缺字段，不影响复盘主流程（与现有快照各节一致）。

### 5.4 提示词

用户消息增加"今日执行（程序判定）"文本段，仅在 `execution` 有内容时出现。只含股票名称、盈亏百分比、持有天数、归因中文名和统计比率；**不含数量、价格、成本金额和备注**。

内置系统提示词增加一节"🧾 执行复盘"，仅当输入含该文本段时输出：2–4 句，说明今天的买卖与昨日剧本、持仓条件是否一致，累计统计里最该改的一类交易是什么。不得改判归因，不得给出价位、数量或操作动作。

已自定义系统提示词的用户不会自动获得新章节（现有行为，设置页已有提示）。

### 5.5 页面

**批次页**（`frontend/src/custom/lots/Page.tsx`）：每行在"删除"旁增加"结清"。点击打开弹窗：

```
结清  600519 贵州茅台   成本 1680.00 · 100 股 · 持有 6 天
卖出价 [ 1722.50 ]   卖出日 [ 2026-11-13 ]
这笔交易  ( ) 按计划止盈  ( ) 按计划止损  ( ) 提前卖出  ( ) 拖延未止损  ( ) 计划外交易
备注（可选） [                              ]
                                   [ 取消 ]  [ 结清并记录 ]
```

卖出日默认今天；每次打开重置表单。成功后失效批次、监控规则、持仓分析、持仓范围风向标和交易记录的查询。

批次列表下方增加默认收起的"已结清"区：按卖出日倒序列出记录（盈亏、持有天数、归因），每行可删除（二次确认，沿用页面现有删除交互）。

**复盘页**（`frontend/src/custom/review/RecapSnapshot.tsx`）：在持仓联动之后增加"今日执行"。默认只显示三行摘要（新建几笔、结清几笔及盈亏、触及止损仍持有几只）；累计统计收起，展开后显示总体与两个分组表。三项都为空且无统计时整节不显示。盈亏注明"卖出价相对登记成本，不含费用"。

## 6. 验证

- 后端 `pytest`：交易记录的校验与存取；结清接口的成功、批次不存在、非法输入、重复结清；`execution` 各字段在有数据、无数据、盘中、收盘价缺失、买入日缺失下的结果；`pnl_pct` 单位；提示词文本段不含数量与金额。并回归 `test_lots.py`、`test_market_recap_*.py`、`test_holding_analysis*.py`。
- 新增与改动文件通过 `ruff check`。
- 前端：批次页与快照面板的组件测试；`pnpm build`。
- 联调：在预览中完成一次结清，生成一篇复盘，确认"今日执行"与"已结清"显示正确。

## 7. 留给实现者决定

- 交易记录模块放在 `backend/app/strategy/` 还是 `backend/app/services/`（按相邻模块的依赖方向选）。
- `had_invalidation` 如何从持仓分析的研究设置里按股票查到。
- 买入日阶段、交易日数复用哪些现有函数。
- `stats` 分组项的具体字段名与前端表格列。
