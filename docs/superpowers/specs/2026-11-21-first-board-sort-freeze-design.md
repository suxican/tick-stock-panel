# 首板候选表盘中排序冻结（设计，已确认）

> 日期 2026-11-21。状态：用户已确认方案，纯前端小改动。

## 1. 目的

盘中快照每 5 秒刷新，候选表默认按“首板优先分”降序（没有评分时按涨幅降序）。分数或涨幅一变，行就换位，用户正要点的那一行可能在点下去的瞬间被换走，误点到别的票。目标：顺序稳定、变化可见、由用户决定何时重排。

## 2. 行为

- **冻结**：数据照常实时更新（价格、涨幅、评分、状态都变），但行的先后顺序保持不变。
- **立即按最新数据重排**的时机，仅限这些用户动作或页面事件：点表头排序、改任一筛选（状态、可提示、主线、形态、重点关注、评分筛选、板块）、星标或取消星标、点提示条“重排”、从其他页签切回“今日盯盘”、首次载入。
- **新出现的行**追加在末尾；**消失的行**直接去掉；其余行保持相对顺序。
- **提示条**：最新排序与当前显示的顺序不同时，在“今日候选 N 条”旁显示按钮“排序有变化 · 点击重排”。其中有刚达到提示条件的候选（自上次重排以来新变为可提示，或新出现且可提示）时，文字为“排序有变化 · 新提示 N 只 · 点击重排”，并用蓝色强调（同时有文字，不只靠颜色）。顺序相同时不显示。
- **新提示不自动置顶**：自动插入会让整张表下移，正好在最可能点击的时刻造成误点；买入提示本身有弹窗通知。
- 股票预览弹窗的上一只、下一只沿用表里当前显示的顺序（冻结后的顺序）。

## 3. 目标、非目标、反目标

**目标**：行不再自己跳位；用户总能知道“现在显示的顺序是不是最新的”。

**非目标**
- 不改排序规则本身（评分、可提示优先、星标置顶都不变），不改后端。
- 不做行移动动画；不做“鼠标悬停才冻结”（键盘和触屏用不上）。
- 不冻结数值：价格、涨幅、评分、结论、可提示状态始终是最新的。

**反目标**
- 冻结导致用户看不到新的可提示候选：必须有提示条和数量。
- 冻结后显示的顺序与预览弹窗翻页顺序不一致。
- 筛选后出现陈旧的行（已不满足筛选的行仍留在表里）。

## 4. 方案对比

| 方案 | 取舍 |
|---|---|
| **A. 冻结顺序，用户手动重排（选定）** | 行为可预期；需要一个提示条 |
| B. 鼠标悬停或聚焦表格时冻结，离开后自动重排 | 不需要按钮；键盘与触屏无效，且离开瞬间整表跳动 |
| C. 只加行移动动画 | 行仍在动，误点问题没解决 |

## 5. 实现要点（我定的）

- 在 `useCandidateView` 里对排序后的结果再套一层“冻结顺序”：纯函数 `applyFrozenOrder(live, previousKeys, keyOf)`，返回显示用的行和新的顺序键；行的键沿用候选表现有的 `${symbol}-${pattern}`。
- 重排时机用一个“重置签名”表示：排序列与方向、各筛选值、被星标的代码、重排计数、是否处于“今日盯盘”页签。签名变化即视为重排。
- `useCandidateView` 新增第四个参数 `active: boolean`（`tab === 'live'`），并多返回 `orderChanged`、`newBuyCount`、`reorder`。
- 状态筛选各分段的计数仍按实时数据算，不受冻结影响。
