# 阶段 2：重点监控名单与严重异动预测接入做T / 持仓分析（简短设计）

> 依据：`docs/猫爪数据对接/猫爪数据对接规划.md` 第 11.2、11.3、11.6 节（决策 2 及其后对做T 的建议）。日期 2026-11-20。

## 目的

两个功能都把「交易所重点监控」和「次日可能触发严重异常波动」作为风险事实：
- 做T：人工账户提示后允许，自动模拟账户暂停；
- 持仓分析：提示后允许采纳。

## 数据（已有每日盘后留档，`data/meoz_archive/v1/`）

| 数据 | 字段 | 适用日期 |
|---|---|---|
| `point_monitor` 重点监控 / 交易所风险提示 | 类型、6 位代码、名称、监控期起止、原因 | 监控期内的每个交易日。读取交易日 D 当天或之前最近一份留档，D 落在 `startdate`–`enddate` 区间内即命中 |
| `anomaly_forecast` 严重异动预测 | 规则（如「30日偏离值-70%」）、已用天数、需达涨跌幅、触发价、状态 | 交易日 T 收盘后算出、作用于下一交易日。交易日 D 读取前一交易日的留档 |

**需要先修的留档问题**：当天结果为空时，现在不写文件，「当天没有预测」和「留档失败」无法区分。改为：这两个数据集遇到空结果也写一个 0 行文件。读取时：
- 文件不存在，视为「不可用」；
- 文件存在但 0 行，视为「无」。

## 读取层（源中立）

新增一个读取函数，把留档转成本地契约：

```
regulatory_reference(day) -> {
  "monitor": {symbol: [{label, start, end, reason}]} | None,
  "anomaly": {symbol: {rule, trigger_price, required_pct, status, as_of}} | None,
}
```

- 返回的代码带交易所后缀。
- `None` 表示「不可用」，不是「无风险」。
- 业务层不读猫爪原始字段。

## 持仓分析

风险状态新增四项，沿用现有的风险标签、逐条确认、服务端复核和提醒暂停：

| id | 含义 |
|---|---|
| `monitored` | 重点监控 / 交易所风险提示，明细为类型、监控期和原因摘要 |
| `anomaly_forecast` | 严重异动预测，明细为规则、触发价和需达涨跌幅 |
| `monitor_unknown` | 监管名单不可用 |
| `anomaly_unknown` | 异动预测不可用 |

风险状态的判断依据文字（AI 可引用的那段）同步加入这四项。

## 做T

- 每个信号附带 `risk_flags`，取值与持仓分析相同，包括两个「不可用」。
- **人工账户**：信号照常评估，详情里显示风险项；建立计划时必须逐条确认，请求带 `acknowledged_risks`。服务端会重新核对：风险已变化，或确认没有覆盖全部风险，都返回冲突。
- **自动模拟账户**：命中任何一项（含「不可用」）就暂停新建计划，暂停原因写明是哪一项。已有计划的风险退出逻辑不变。
- 盘中不另外请求猫爪：只用盘前已有的留档，不增加调用。

## 不做的

- 不自动交易、不自动作废已有计划。
- 不把这两项写进策略打分。
- 严重异动预测不用本地 `abnormal_moves` 推算替代，那是另一个口径，只在后续对账时使用。

## 风险

- 重点监控名单是「当前名单」，用前一交易日 15:40 的留档判断当日，可能漏掉当天新增的监控。
- 严重异动预测在盘后才产出，盘中新出现的预测这一版拿不到。
- 留档本身失败时，做T 自动模拟会因「不可用」暂停，这是有意的保守选择。
