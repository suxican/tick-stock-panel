# 首板页顶部合并（设计，待审阅）

> 日期 2026-11-20。状态：用户已拍板“市场环境、情绪阶段撤到折叠区，其余按本方案”。本文为短设计，待用户审阅后写实施计划。纯前端改动。

## 1. 目的

首板页顶部现在从上到下依次是：温度条、6 个状态标签、日期行、提示框、“昨日首板反馈”面板。封板率、昨日首板均涨等数字重复出现两三次，真正决定出手强度的数字被工程状态淹没。目标是把顶部合成一块：先给结论，再给 4–5 个关键数字和昨日主线，其余折叠。

## 2. 目标、非目标、反目标

**目标**
- 顶部第一屏只回答：温度档位、关键数字、昨日主线、有没有阻断买入的问题。
- 同一个数字只出现一次。
- 阻断买入的原因（市场环境不允许、实时行情受阻、封单轮询未开）仍然一眼能看到。

**非目标**
- 不改后端、不改任何买入逻辑，不改候选表及其筛选。
- 不改温度的口径与算法。
- 不重做“昨日首板反馈”展开后的内容（范围切换、分布、个股表、板块对照）。

**反目标**
- 把会阻断买入的信息折叠起来，让人误以为可以买。
- 缺失数据用 0 填充，或者数字消失后没有占位。

## 3. 布局

```
┌ [首板温度 · 休息]  11/20 收盘 ────────── 数据与环境 ▾ ┐
│ 封板率 68%  昨日首板均涨 -4.48%  晋级二板 1/19  涨停:跌停 30:61  高度 4 板 │
│ 昨日主线：先进封装 · 光刻胶 · 算力租赁                              │
│ 已收盘，显示 11/20 收盘数据                                        │
└──────────────────────────────────────────────────────────────┘
昨日首板反馈  样本 11-19 · 表现 11-20   [全部|主板|双创]  [展开分布]
```

- **第一行**：温度徽章和时段在左；右侧是折叠开关“数据与环境 ▾”，开关上保留现有数据覆盖摘要标签。
- **第二行（关键数字）**：封板率、昨日首板均涨（沿用温度徽章里的两项）、晋级二板（昨日首板中当前二板数／样本数，取自反馈 `groups.all`）、涨停:跌停、连板高度（取自盘中梯队 `market_ladder`）。缺失显示“—”，不显示 0。
- **第三行**：昨日主线前三名（概念优先，沿用现有取舍）。主线待确认时显示“待确认”。
- **状态行**：收盘时只显示一句“已收盘，显示 {交易日} 收盘数据”；其他状态沿用后端 `message`；后端 `global_blocked_reasons` 只在盘中（ready）出现时列出，收盘或非交易时段不再逐条罗列。
- **“数据与环境”折叠区**：市场环境、情绪阶段、今日梯队三个标签（保持现有文案和悬停说明）、交易日期／快照时间／规则版本、现有数据覆盖明细面板。
- **始终可见的告警**（不折叠）：
  - 市场环境不允许提示（`environment.allowed === false`）：琥珀色一条，写明环境名称和“暂不允许提示”。
  - 实时行情受阻：沿用现有提示和“检查实时行情数据源”链接。
  - 盘中封单未开启：沿用现有链接。
- **“昨日首板反馈”面板**：折叠态不再显示 KPI 行（数字已在顶部）；标题、日期、范围切换、展开按钮保留。展开后内容不变。

## 4. 我定的几个选择（请核对）

1. **按钮和标题文案不改**：仍叫“昨日首板反馈”“展开分布／收起分布”。现有大量测试按这些文字查找，改名收益小。
2. **顶部数字只取“全部”范围**。主板／双创的分别数字留在展开后的面板里，范围切换也留在原处。
3. **折叠区默认收起，不记忆展开状态**。顶部只是结论，不需要用户反复展开；与“昨日首板反馈”面板自带的展开记忆不冲突。
4. **旧后端（没有盘中梯队或温度字段）**：缺哪项显示“—”或不显示该项，不报错。

## 5. 方案对比

| 方案 | 做法 | 取舍 |
|---|---|---|
| A. 就地精简（选定） | 保留现有组件，改 `LiveStatus` 的结构，把标签搬进折叠区，反馈面板去掉折叠态 KPI | 改动面小，现有测试多数只需改断言位置 |
| B. 新建统一顶部组件 | 新写一个组件，把 `LiveStatus`、反馈折叠态都吃掉 | 结构最干净，但要重写大量已有测试，风险高 |
| C. 只调样式不改结构 | 缩小标签、压缩间距 | 重复数字和信息过多的问题没有解决 |

## 6. 留给实现者

- 关键数字行是放进 `TemperatureBadge` 还是做同级新组件，由实现者决定；温度徽章现有的 `data-first-board-temperature` 属性和测试要保持有效。
- 折叠区的无障碍写法（`aria-expanded`、`aria-controls`）沿用现有 `LiveStatus` 的做法。
- 受影响的现有测试：`FirstBoard.test.tsx` 中涉及“盯盘状态”“情绪阶段”“盘中梯队”“昨日主线”“市场环境”的断言，以及 `YesterdayFeedback.test.tsx` 中折叠态 KPI 的断言，需要按新结构调整。
