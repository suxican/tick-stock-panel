# 首板临板焦点区（设计，已确认）

> 日期 2026-11-21。状态：用户已确认方案，纯前端、不改后端和买入逻辑。

## 1. 目的

盘中真正需要秒级决策的，只有“快封板、还没封”的那一两只。现在它们混在候选表里，一行十几列，还会随排序、筛选变化位置。目标：在候选表上方用大卡片单独展示，一眼看到能不能买、买多少、不能买差在哪。

## 2. 行为

- **入选**：快照里状态为“临近涨停”（后端判定：距涨停价 ≤ 规则里的临近距离，默认 3%，且最高价还没触及涨停价）的候选。可提示（`can_buy`）的排前面，其余按距涨停从近到远。最多 3 张；多出的在标题里写“另有 N 只，见下表”。
- **不受表格筛选影响**：卡片直接读快照里的候选，不经过表格的筛选和冻结顺序。
- **卡片内容**（沿用表格里的现成组件和口径）：名称、代码、板块标签（龙头、中军、主线）；现价、涨幅、距涨停；首板优先分摘要；板块联动摘要；一句结论（可提示、首要阻断原因或受全局条件暂停）；可提示时显示“模拟买入”按钮和建议金额。点名称打开股票预览。
- **能买与不能买**：可提示的卡片用蓝色描边和浅蓝底；不能买的卡片灰显，靠结论文字说明原因，不只靠颜色。
- **按钮规则与表格里的“模拟买入”完全一致**：同样调用 `onBuy(event_id, suggested_amount)`，同样在 `canOrder` 为假、缺少 `event_id` 或建议金额时禁用。
- **卡片位置稳定**：已显示的卡片在仍然“临近涨停”期间不换位；有卡片消失时，空位由下一只补上；新出现的追加在后面。
- **高度固定**：这一块的内容区固定为 16rem（`h-64`），内容超出时在区内滚动，没有候选时显示一行“当前没有临近涨停的候选”，所以卡片出现或消失都不会把下面的表格挤动。
- **只在盘中有效时显示**：快照状态为 ready 且数据有效（与表格里 `current` 同一个判断）时才显示；休市、行情过期、数据错误时整块不渲染。

## 3. 目标、非目标、反目标

**目标**：盘中最需要决策的候选永远在固定位置、固定样式，且不会因为刷新而位移。

**非目标**
- 不改“临近涨停”的判定，不改买入条件、建议金额、阻断原因。
- 不加声音、闪烁或新的通知；不放已封板（涨停价观察）的候选，封住后不再有买入提示。
- 不新增配置，不改后端。

**反目标**
- 卡片上的“模拟买入”能点，但表格里同一只股票的按钮不可点（或相反）。两处必须同一判定。
- 用户在表格里筛选后，快封板的候选从卡片里消失。
- 卡片出现或消失让表格位移，造成误点。

## 4. 方案对比

| 方案 | 取舍 |
|---|---|
| **A. 表格上方独立卡片区（选定）** | 位置固定、与表格互不影响；买入入口出现两处，需要保证口径一致 |
| B. 把表格里的临近涨停行置顶并放大 | 不新增入口；仍受筛选和排序影响，表格行变高更难读 |
| C. 悬浮窗口 | 遮挡表格，窄屏不友好 |

## 5. 我定的选择（请核对）

1. **最多 3 张**，来自你最初的建议；超出只给数量。
2. **不能买的候选也显示**（灰显并写原因），让你知道“差在哪”。
3. **固定高度**：为避免位移，这一块在盘中始终占位；代价是没有候选时也占一行高度的空白提示。
4. **卡片与表格的按钮口径**用同一段判定，由实现者抽成共用，避免两处各写一份。
5. **卡片不记忆展开状态**，也没有折叠；它只是盘中的一块固定信息区。

## 6. 验证

- 纯函数测试（选哪些、怎么排、怎么保持位置）和页面级测试（入选、排序、数量上限、不受筛选影响、位置稳定、按钮口径、休市隐藏、固定高度）。
- `pnpm exec vitest run src/custom/first-board`、`pnpm build`。
- 休市时没有临近涨停的候选，浏览器里只能看到整块不出现；盘中表现要等交易日实测，验证报告里要注明。
